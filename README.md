# KdmCopilot

KdmCopilot 是面向个人工作流的长周期 AI Agent Harness。它不是只负责一次问答的聊天界面，而是为复杂任务提供运行时保障：管理任务上下文和执行状态，协调多个 Agent，保存长期记忆，并记录可查询的执行轨迹。

当任务需要跨多轮对话、多个工具调用或多次恢复才能完成时，KdmCopilot 负责让 Agent 能持续推进任务，同时让人能够检查它做过什么、为什么这样做以及结果是否可信。

## Harness 解决的问题

单次模型调用无法天然处理长周期任务：对话累积后会超出上下文窗口，任务中断后容易丢失状态，多个 Agent 的结果难以协调，执行过程也难以回放和核查。

KdmCopilot 将这些问题放在 Agent 运行时中处理，而不是依赖一次提示词解决：

- 管理任务所需的上下文，保留近期和关键内容，并在接近窗口限制时压缩旧内容
- 持久化会话、任务检查点和持续目标状态，支持任务跨轮次继续执行
- 拆分并协调子 Agent 工作，保留父子任务关系和结果交付状态
- 将工作记忆沉淀到长期记忆，避免每次任务从零开始
- 记录模型调用、工具调用、状态变化和任务关系，提供可追踪的执行证据

## 核心能力

### 上下文与状态管理

根据模型上下文预算构建任务输入，在任务变长时进行上下文压缩，同时保留持久化会话记录。持续目标和检查点使任务可以在多个执行回合之间恢复，而不是因一次中断失去进度。

### 多 Agent 协作

主 Agent 可以将独立工作委派给子 Agent，收集结果后继续决策。系统维护子任务的创建、执行状态、结果交付及父子关联，避免协作过程只停留在最终文本汇总。

### 长期记忆

区分短期会话历史和工作区长期记忆。前者服务当前任务的连续性，后者沉淀可复用的信息与工作习惯，供后续任务使用。

### 执行轨迹审计

为对话、模型调用、工具执行、状态检查点和子 Agent 生命周期保存可查询证据。执行轨迹可用于定位失败、复盘任务过程和核查实际执行结果。

### 工具与接入

通过浏览器工作台、终端、消息渠道和 OpenAI 兼容 API 接入。Agent 可在权限与配置范围内使用文件、命令、网页、MCP、定时任务、图像生成等工具，并支持多模型与备用模型配置。

## 本地启动

推荐使用 Docker Compose 运行。准备好 Docker 后，在仓库根目录执行：

```bash
docker compose up -d --build
```

启动完成后，打开 [http://localhost:8765](http://localhost:8765)。运行数据保存在 `runtime/`；首次使用前，请按照自己的模型服务和密钥配置该目录中的配置文件。

查看服务状态与日志：

```bash
docker compose ps
docker compose logs -f
```

停止服务：

```bash
docker compose stop
```

## 开发

运行环境要求 Python 3.11+。前端构建需要 Bun 或 npm。

```bash
python -m pip install -e ".[dev]"
cd webui && bun install && bun run build
```

常用检查：

```bash
ruff check .
pytest
cd webui && bun run test
```

## 项目结构

- 核心运行时：Agent 调度、模型接入、工具、渠道、记忆与审计
- `webui/`：浏览器端工作台与执行轨迹展示
- `docs/`：配置、部署和开发文档
- `runtime/`：本地运行数据与工作区
