## 四、真实浏览器开考与原子发送

必须严格执行以下顺序：

1. 创建 page 前注册 console error、page error、request failed、WebSocket close/error 监听。
2. 登录 WebUI，打开新对话路由 `#/new`，确认页面没有既有用户消息。
3. `#/new` 在首次发送前尚无 chat ID；此时禁止等待 chat ID、attached 状态或 Session 创建。
4. 取得已认证的 Playwright `page` 后，只调用 V3 `prompt_send.py` 的固定发送函数。
5. 固定函数成功返回后，再等待新 chat ID、`websocket:<uuid>` Session、Trace ID 和 main Run ID。
6. 持续观察，直至 main 与 child 达到终态或总等待达到 15 分钟。

正式发送必须使用以下调用。不得自行实现替代版本：

```python
import sys
from pathlib import Path

version_dir = Path("_other/评测/审计运行轨迹/V3").resolve()
sys.path.insert(0, str(version_dir))
from prompt_send import extract_prompt, load_expected, send_exact_prompt

prompt = extract_prompt(version_dir / "试卷.md")
expected = load_expected(version_dir / "prompt-manifest.json")
input_integrity = send_exact_prompt(page, prompt, expected)
```

严禁 `press_sequentially`、`keyboard.type`、`press("Enter")`，也禁止逐行填充、粘贴后按 Enter 或
通过任何键盘事件输入换行。`send_exact_prompt` 内部使用一次 `fill()` 和一次按钮 `click()`；发送
前读取 `input_value()`，发送后确认 UI 恰好新增一条用户消息且文本哈希一致。

将 `input_integrity` 加上发送 UTC 写入 `输入完整性.json`，不得保存 prompt 原文。若固定函数报错、
UI 不是恰好新增一条消息或哈希不符，立即停止：本场无效，结论为“证据不足，无法判定”，不评分，
不重跑，也不得使用该场任何 Run 证明三路径或关系功能。

## 五、安全取证

使用短期 bearer 按实际 cursor 收齐：

```text
GET /api/audit/traces?session_key=<encoded>
GET /api/audit/traces/<trace-id>/graph?level=trace
GET /api/audit/traces/<trace-id>/graph?level=trace_full
GET /api/audit/traces/<trace-id>/events?limit=200
```

Event 分页至 `next_cursor=null`。终态后至少三轮、每轮间隔 5 秒观察 event count、Run 终态和 index
revision 不变，才进入评分。

| 证据主题 | 必须确认的事实 |
|---|---|
| 三次读取 | 三组 `ToolStarted/ToolFinished` 使用不同 tool call ID |
| 恢复摘要 | 首个失败节点为 `recovered/recorded`，恢复 Event 精确指向第三次成功，不指向同 basename 的第二次 |
| 持久化 link | `recovery_of_tool_call_ids` 由指定 pytest 验证，不假定公开 Events API 返回内部字段 |
| 失败诊断 | Graph 有根因、影响、恢复、evidence source 和安全 `raw_events` 回链 |
| 关系边 | 只记录 API 实际存在的边；不存在记零，不把 Tool recovery 推成 `retry_of` |
| Run 结构 | 分别统计 main、child、continuation，无关系证据时不自行推导 |
| 响应安全 | Graph/Events 不含完整参数、结果、query、认证材料或绝对敏感路径 |

## 六、UI、测试与评分

按 V3 试卷第一至第五题完成 UI 操作并保存安全截图，再运行第六题真实 Chromium Playwright 和
第七题指定 pytest。不得以真实网络偶发超时替代确定性故障注入。

严格按 100 分制评分。每题记录得分、endpoint 或 DOM、字段路径、evidence ID、观察值、期望值和
归因。结论只能使用：通过、有条件通过、被测 Agent 不通过、评测环境不可执行、证据不足，无法判定。
总分至少 85，且第二、第三题各达到满分 80% 才可“通过”。
