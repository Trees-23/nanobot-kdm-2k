# 审计运行轨迹改进评测试卷 V3

版本：2026-07-31

## 评测目标

验证运行轨迹从 Runner、Audit Event、Graph API 到 WebUI 的结构化错误诊断、显式恢复证据、
原始 Event 导航、Payload 安全读取、关系聚焦和时间线滚动。V3 同时把“唯一输入必须作为一条
完整消息发送”提升为可执行门禁，避免自动化把多行文本中的换行误当成发送快捷键。

满分 100 分。任何场景若使用旧 gateway 产生数据、只凭截图猜测后端字段，或输入完整性门禁
失败，均不得计分。

## 前置门禁

以下六项必须全部满足，否则不进入计分。

| 门禁 | 通过条件 |
|---|---|
| 版本一致 | gateway 与 WebUI 来自包含本次改造的同一提交 |
| 数据新鲜 | 重启 gateway 后产生全新评测 Run；不要求历史 Audit 补写新字段 |
| 证据真实 | 保留生产 Audit JSONL 原始证据，不手工编辑 Event 或 Payload |
| 输入来源 | 由 `prompt_send.py` 从本试卷指定章节提取唯一 `text` 代码块 |
| 输入原子性 | 使用 `fill()`，发送前后哈希一致，只点击一次发送按钮，UI 恰好新增一条用户消息 |
| Fixture 可读 | manifest 校验通过，fixture 已部署到实际 Agent workspace 的 V3 目标路径 |

基础设施或版本门禁失败，结论为“评测环境不可执行”。已开考但输入原子性失败，判定该场无效，
结论为“证据不足，无法判定”，不得评分，也不得把分段消息产生的 Run 用作功能证据。

## Fixture 部署契约

权威 fixture 保存在本版本的 `V3/fixtures/`。监考器必须在创建 Session 前执行：

```bash
python _other/评测/审计运行轨迹/V3/fixture_stage.py \
  source-verify --workspace <agent-workspace-host-path>
python _other/评测/审计运行轨迹/V3/fixture_stage.py \
  stage --workspace <agent-workspace-host-path>
python _other/评测/审计运行轨迹/V3/fixture_stage.py \
  verify --workspace <agent-workspace-host-path>
```

当前 Docker 部署通常将容器 `/home/nanobot/.nanobot/workspace` 映射到仓库 `runtime/workspace`，
但监考器必须核验真实 mount。部署工具只允许写入 `evals/audit-trace-v3/fixtures/`；发现不同内容、
符号链接、额外文件或哈希不一致时必须停止。取证后再次 `verify`，通过后才可 `cleanup`。

## 发送给被测 Agent 的唯一输入

监考器必须由 `prompt_send.py` 提取、校验和发送下面代码块。禁止手工重打，禁止
`press_sequentially`、`keyboard.type` 或任何通过 Enter 输入换行的方法：

```text
这是一次审计运行轨迹黑盒评测。请严格按顺序执行下面的 Tool 调用，不要合并步骤，不要因为某一步失败而停止，也不要自行改写路径。

1. 使用 read_file 读取：
   evals/audit-trace-v3/fixtures/recovery-target/runtime/config.json
   这个路径预期不存在。记录失败后继续。

2. 使用 read_file 读取：
   evals/audit-trace-v3/fixtures/unrelated/config.json
   它与第一步 basename 相同，但属于不同逻辑资源。成功后继续。

3. 使用 read_file 读取：
   evals/audit-trace-v3/fixtures/recovery-target/config.json
   它是第一步的确定性纠错路径。成功后继续。

4. 使用 web_search 搜索：nanobot audit trace deterministic evaluation
   无论成功、普通失败还是 timeout 都继续。不要重复搜索来人为制造恢复判断。

5. 使用 spawn 创建一个 `required=false`、label 为 `audit-child-check` 的子任务。子任务先读取
   evals/audit-trace-v3/fixtures/child/context.txt，再执行 `sleep 20`，最后原样返回文件中的 marker。不要让子任务修改任何文件。

6. spawn 返回后不要等待子任务，不再调用任何 Tool，立即只回复：AUDIT_PARENT_RELEASED

7. child 结果后续回流并触发 continuation 时，不调用任何 Tool，只回复：AUDIT_CONTINUATION_RECEIVED

不要读取或修改 Audit JSONL，也不要声称自己验证了 Graph UI。
```
