# 审计运行轨迹 V3 更新说明

V3 修复 V2 监考自动化使用 `press_sequentially` 输入多行提示词时，换行触发 WebUI Enter
发送快捷键、将唯一输入拆成 8 条消息的问题。V1、V2 及其运行记录保持冻结。

| 项目 | V2 | V3 |
|---|---|---|
| 多行输入 | 泛化描述为“逐字符发送”，未限制具体 Playwright API | 强制 `textarea.fill(完整提示词)` |
| 发送动作 | 未明确排除 Enter | 禁止 Enter，只允许点击一次“发送消息”按钮 |
| 发送前校验 | 只要求记录摘要 | `input_value()` 必须与 manifest 的字符数、字节数和 SHA-256 一致 |
| 发送后校验 | 事后统计消息数 | UI 必须恰好新增一条用户消息，且其文本哈希一致 |
| 新会话时序 | 曾在 `#/new` 发送前等待 chat ID | 发送前不等待 chat ID，点击后再等待 Session 创建 |
| 固定工具 | 无 | 新增 `prompt_send.py`，封装提取、填充、点击与前后断言 |
| Fixture 路径 | `evals/audit-trace-v2/fixtures/` | `evals/audit-trace-v3/fixtures/` |

V2 的 `20260731-183519` 运行记录是无效场次的真实证据，不删除、不改写，也不将其中因分段消息
产生的 Run 用于功能评分。V3 只修复评测协议，不修改 nanobot 产品的 Enter/Shift+Enter 交互。

## 固定发送器用法

先验证试卷与 manifest，并用真实 Chromium 运行本地协议自检：

```bash
python _other/评测/审计运行轨迹/V3/prompt_send.py --self-test
```

正式监考脚本登录 WebUI、打开 `#/new` 并取得已认证的 Playwright `page` 后，调用：

```python
from prompt_send import extract_prompt, load_expected, send_exact_prompt

prompt = extract_prompt(version_dir / "试卷.md")
expected = load_expected(version_dir / "prompt-manifest.json")
integrity = send_exact_prompt(page, prompt, expected)
```

不得把认证 storage state、cookie 或 token 写入 V3 目录。`integrity` 只包含计数、哈希、长度和
发送后页面 URL，不包含提示词原文。
