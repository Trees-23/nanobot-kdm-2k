# 审计运行轨迹改进评测试卷 V4

版本：2026-07-31

## 评测目标

验证运行轨迹从 Runner、Audit Event、Graph API 到 WebUI 的结构化错误诊断、显式恢复证据、原始
Event 导航、Payload 安全读取、关系聚焦和时间线滚动。V4 保留 V3 的单消息原子发送协议，并修正
部署版本门禁：只比较浏览器实际访问的 WebUI 与运行中 gateway 容器的产物，不比较未参与部署的
宿主机 dist。

满分 100 分。输入完整性失败、基础设施不可用或实际部署缺少关键能力时不得计分。

## 前置门禁

以下六项必须全部满足：

| 门禁 | 通过条件 |
|---|---|
| 部署一致 | `deployment_gate.py` 证明 HTTP 实际返回的 index 和主 bundle 与运行中 gateway 容器内 dist 完全一致 |
| 功能版本 | 部署 bundle 包含 V4 要求的审计导航、关系聚焦和自动加载上限标记，关键后端文件与仓库一致 |
| 数据新鲜 | 重启 gateway 后产生全新评测 Run，不要求历史 Audit 补写字段 |
| 证据真实 | 不手工编辑 Event、Payload 或生产 Audit JSONL |
| 输入原子 | `prompt_send.py` 使用一次 `fill()` 和一次按钮点击，前后哈希一致且 UI 只新增一条用户消息 |
| Fixture 可读 | manifest 校验通过并部署到真实 Agent workspace 的 V4 目标路径 |

宿主机 `nanobot/web/dist` 是独立构建参考，不在当前容器请求路径中。它与容器 dist 的文件名或哈希
不同，只能记录为提示，禁止单独据此判定“评测环境不可执行”。

## Fixture 部署契约

```bash
python _other/评测/审计运行轨迹/V4/fixture_stage.py \
  source-verify --workspace <agent-workspace-host-path>
python _other/评测/审计运行轨迹/V4/fixture_stage.py \
  stage --workspace <agent-workspace-host-path>
python _other/评测/审计运行轨迹/V4/fixture_stage.py \
  verify --workspace <agent-workspace-host-path>
```

当前 Docker 部署通常把容器 `/home/nanobot/.nanobot/workspace` 映射到仓库 `runtime/workspace`，
但必须核验真实 mount。工具只允许写入 `evals/audit-trace-v4/fixtures/`；出现不同内容、符号链接、
额外文件或哈希不符时停止。取证后再次 `verify`，通过后才可 `cleanup`。


| 评分点 | 判定标准 | 分值 |
|---|---|---:|

| 判定解释 | 依据同一 Run 的资源指纹和恰好增删一个中间目录，不按 basename、Tool 名或 Run 成功推断 | 3 |

## 发送给被测 Agent 的唯一输入

必须由 V4 `prompt_send.py` 提取、校验和发送下面代码块：

```text
这是一次审计运行轨迹黑盒评测。请严格按顺序执行下面的 Tool 调用，不要合并步骤，不要因为某一步失败而停止，也不要自行改写路径。

1. 使用 read_file 读取：
   evals/audit-trace-v4/fixtures/recovery-target/runtime/config.json
   这个路径预期不存在。记录失败后继续。

2. 使用 read_file 读取：
   evals/audit-trace-v4/fixtures/unrelated/config.json
   它与第一步 basename 相同，但属于不同逻辑资源。成功后继续。

3. 使用 read_file 读取：
   evals/audit-trace-v4/fixtures/recovery-target/config.json
   它是第一步的确定性纠错路径。成功后继续。

4. 使用 web_search 搜索：nanobot audit trace deterministic evaluation
   无论成功、普通失败还是 timeout 都继续。不要重复搜索来人为制造恢复判断。

5. 使用 spawn 创建一个 `required=false`、label 为 `audit-child-check` 的子任务。子任务先读取
   evals/audit-trace-v4/fixtures/child/context.txt，再执行 `sleep 20`，最后原样返回文件中的 marker。不要让子任务修改任何文件。

6. spawn 返回后不要等待子任务，不再调用任何 Tool，立即只回复：AUDIT_PARENT_RELEASED

7. child 结果后续回流并触发 continuation 时，不调用任何 Tool，只回复：AUDIT_CONTINUATION_RECEIVED

不要读取或修改 Audit JSONL，也不要声称自己验证了 Graph UI。
```
