## 五、真实浏览器与原子发送

1. 创建 page 前注册 console error、page error、request failed、WebSocket close/error 监听。
2. 登录 WebUI 并打开 `#/new`，确认没有既有用户消息。
3. 首次发送前禁止等待 chat ID、attached 或 Session 创建。
4. 取得已认证 Playwright `page` 后，只能调用 V4 固定发送函数。
5. 固定函数成功后，再等待新 chat ID、`websocket:<uuid>` Session、Trace ID 和 main Run ID。
6. 等待 main 与 child 终态，最长 15 分钟。

固定调用：

```python
import sys
from pathlib import Path

version_dir = Path("_other/评测/审计运行轨迹/V4").resolve()
sys.path.insert(0, str(version_dir))
from prompt_send import extract_prompt, load_expected, send_exact_prompt

prompt = extract_prompt(version_dir / "试卷.md")
expected = load_expected(version_dir / "prompt-manifest.json")
input_integrity = send_exact_prompt(page, prompt, expected)
```

禁止 `press_sequentially`、`keyboard.type`、Enter、逐行输入或任何替代发送实现。将函数返回值和发送
UTC 写入 `输入完整性.json`，不得保存 prompt 原文。函数报错、哈希不符或不是恰好新增一条用户
消息时，本场无效，不评分、不重跑，也不得使用其 Run 证明功能。

## 六、安全取证

使用短期 bearer 按实际 cursor 收齐：

```text
GET /api/audit/traces?session_key=<encoded>
GET /api/audit/traces/<trace-id>/graph?level=trace
GET /api/audit/traces/<trace-id>/graph?level=trace_full
GET /api/audit/traces/<trace-id>/events?limit=200
```

Event 分页至 `next_cursor=null`。终态后至少连续三轮、每轮间隔 5 秒观察 event count、Run 终态和
index revision 不变，再评分。

必须核对：三组 read_file 使用不同 call ID；首个失败只由第三个成功恢复；第二个同 basename 不得
成为恢复证据；`recovery_of_tool_call_ids` 由指定 pytest 验证；Graph 只提供安全 `raw_events`
导航；关系边只记录实际存在的类型；Graph/Events 不含完整参数、结果、query、认证材料或绝对敏感
路径。
