# 执行与监考审计运行轨迹试卷 V1 的提示词

把本文件整段作为一个完整任务交给监考 AI。该任务只授权创建一个新考试 Session、运行 V1、
读取安全 Audit 证据并写入新的 V1 运行记录；不授权修改产品代码、配置、试卷、fixture、会话历史
或权威 Audit 数据。

---

你是 nanobot 审计运行轨迹专项评测监考器。不要替被测 Agent 答题，不追加提示，不手工制造
Event、Payload、恢复关系或 child 结果。必须通过真实浏览器打开 nanobot WebUI，在全新 WebSocket
Session 中发送权威试卷的唯一输入，持续观察 UI 与 Audit API，最后按试卷评分。

仓库根目录：

```text
/home/kdm/TL-WorkSpace/TL-Project/AIworker/nanobot-kdm-2k
```

权威资产：

```text

_other/评测/审计运行轨迹/V1/监考提示词.md
_other/评测/审计运行轨迹/V1/更新清单.md
_other/评测/审计运行轨迹/V1/fixtures/
```

## 一、不可变约束

[] a. 完整阅读 `AGENTS.md`、`.agent/security.md`、主题说明和 V1 试卷；实际字段以当前产品代码与 API 响应为准。

[] b. 禁止 reset、checkout、clean、commit、push；保留用户修改。

[] c. 禁止修改产品、配置、试卷、fixture、历史 Audit JSONL、payload、catalog 或索引。

[] d. 禁止为了通过而追加消息、重跑失败步骤、手工补 child 结果或伪造截图。

[] e. bootstrap secret、bearer、cookie 和 ticket 仅保存在内存，不打印、不截图、不归档。

[] f. Graph 列表只记录安全 ID、类型、状态、计数、时间和关系；Payload 仅在试卷要求的显式 UI 操作中查看，不归档原文。

## 二、环境前检

前检最多 10 分钟。记录安全摘要：`git status --short`、当前 commit、gateway health、WebUI 与
WebSocket 可用性、Audit API/index 状态、Agent workspace、`spawn` 可用性以及 V1 三个 fixture
文件存在且内容 SHA-256 稳定。

必须确认 gateway 与 WebUI 来自同一包含本次功能的提交；若页面出现“当前 Graph 未提供原始
Event 导航信息”，先判定是否仍为旧 gateway，不得直接给功能判失败。关键能力不可用时结论为
“评测环境不可执行”，不要发送考试。

在创建运行记录前计算 `试卷.md`、`监考提示词.md`、`更新清单.md` 和三个 fixture 的 SHA-256。
从试卷“发送给被测 Agent 的唯一输入”一节结构化提取唯一 `text` 代码块，不手工重打。

## 三、真实浏览器开考

[] a. 在创建 page 前注册 console error、page error、request failed、WebSocket close/error 监听。

[] b. 登录后创建全新对话，确认得到新的 `websocket:<uuid>` Session，不复用历史 Session。

[] c. 把试卷唯一输入逐字符发送，记录字符数、UTF-8 字节数和发送前后 SHA-256，不归档消息原文。

[] d. 记录发送 UTC、Session key、Trace ID、main Run ID；随后持续观察直至 main 和 child 达到终态或超过 15 分钟。

[] e. 开考后发现产品问题只记录，不现场修复，也不自动开始第二场。

## 四、安全取证

使用短期 bearer 读取并按实际 cursor 收齐：

```text
GET /api/audit/traces?session_key=<encoded>
GET /api/audit/traces/<trace-id>/graph?level=trace
GET /api/audit/traces/<trace-id>/graph?level=trace_full
GET /api/audit/traces/<trace-id>/events?limit=200
```

逐项核对：

[] a. 三次 `read_file` 的 ToolStarted/ToolFinished 与不同 tool call ID。

[] b. Graph 中第一个失败节点的 `recovery_status=recovered`、`evidence_source=recorded`，且 `recovered_by_event_id` 指向第三个成功终态 Event，不指向第二个同 basename 调用。持久化 `recovery_of_tool_call_ids` 由试卷指定的聚焦 pytest 验证，不假定公开 Events API 返回该内部字段。

[] c. Graph 失败节点的根因、影响、恢复、evidence source 和安全 `raw_events` 回链。

[] d. 记录 API 中实际存在的 `caused_by/retry/retry_of`、`sequence`、`parent_run/spawn_branch`、`result_return/resumed_from` 边；不存在的关系记录零命中，不把 Tool recovery 推导成 `retry_of`。

[] e. main、child、continuation 分别计数；没有关系证据时记录零命中，不自行推导。

[] f. Graph/Events 响应不含完整参数、结果、query、Authorization、cookie、token 或绝对敏感路径。

Event 分页至 `next_cursor=null`。终态后至少连续三轮、每轮间隔 5 秒观察到 event count、Run 终态
和 index revision 不变，才进入评分。

## 五、UI 验收

按试卷第一至第五题操作并截图：失败 Tool 根因、原始 Event 区域、时间线定位、四种关系聚焦、
零命中、main Run 定位、首个异常和图例。截图前关闭 Payload，确保无 secret、完整 Tool 输入或
输出。第六题运行原生 Python Playwright；第七题运行指定 pytest，不用真实网络偶发超时代替。

## 六、评分与结论

严格按试卷 100 分评分。每题记录：得分、权威 endpoint/DOM、字段路径、evidence ID、观察值、
期望值和归因。结论只能是：

```text
通过
有条件通过
被测 Agent 不通过
评测环境不可执行
证据不足，无法判定
```

总分至少 85 且第二、第三题各达到满分 80% 才可“通过”。基础设施阻断不算 Agent 失败；字段
缺失且无法证明原因时为证据不足，不得猜测。

创建全新目录：


至少包含：

```text
截图/原始事件.png
截图/关系聚焦.png
截图/时间线.png

```

归档不得包含 token、cookie、ticket、Payload 原文、模型内容、完整 Tool 参数/结果或 Audit JSONL
副本。`评分结果.json` 必须包含版本、权威文件哈希、Session/Trace/Run ID、各题得分、证据字段、
总分、结论和风险。

## 八、结束自检

复核权威文件哈希未变，运行 `git diff --check` 和 `git status --short`，确认只有本场新 Session 的
append-only 数据和新的运行记录。最终回复给出结论、总分、Session/Trace、三路径恢复判定、四类
关系命中、原始 Event/Payload 状态、Playwright/pytest 结果、运行记录目录和未完成的人工验收。
