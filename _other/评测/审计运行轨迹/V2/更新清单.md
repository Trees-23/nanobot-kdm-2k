# 审计运行轨迹 V2 更新说明

V2 修复 V1 将权威 fixture 放在仓库目录、但被测 Agent 从独立 runtime workspace 解析相对路径的
部署缺口。V1 及其运行记录保持冻结。

| 项目 | V1 | V2 |
|---|---|---|
| 权威 fixture | `V1/fixtures/` | `V2/fixtures/`，由 manifest 固定 SHA-256 |
| Agent 可见路径 | 错误地假定仓库相对路径可见 | `evals/audit-trace-v2/fixtures/`，相对于真实 Agent workspace |
| 环境准备 | 只检查源文件 | 使用 `fixture_stage.py` 部署并再次校验目标文件 |
| 覆盖策略 | 未定义 | 同路径不同内容时拒绝覆盖 |
| 清理策略 | 未定义 | 仅在目标文件与 manifest 完全一致时清理 |
| 考试输入 | 引用 `_other/评测/.../V1/fixtures` | 引用 workspace 内 `evals/audit-trace-v2/fixtures` |

当前 Docker 部署中，容器 `/home/nanobot/.nanobot/workspace` 映射到宿主机仓库的
`runtime/workspace`。监考器必须验证实际 mount，不得把宿主机 `~/.nanobot/workspace` 当成容器
workspace。
