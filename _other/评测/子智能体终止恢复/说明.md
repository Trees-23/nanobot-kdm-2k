# nanobot 子智能体终止与恢复综合评测

本主题验证 required/optional 子智能体从执行、取消、强杀、deadline、重启恢复、结果认领、Audit
投影到 WebUI 双端定位的完整链路。它针对运行时真实性，不以单元测试、合成 Audit fixture 或按钮可点击
代替真实进程与浏览器证据。

当前版本为 `V2`：

```text
V2/试卷.md
V2/监考提示词.md
```

V1 已在 `20260801-200601` 产生正式运行记录，保持冻结。V2 的升级原因是 V1 的 Tool recovery
正例要求模型声明内部 Audit 字段，并使用不满足路径纠正规则的文件名；这会把产品契约错误地变成题目
前提。V2 改为由 Runtime 自己形成证据，失败路径为 `recovery-target/missing/config.json`，成功路径为
`recovery-target/config.json`，且监考环境明确关闭 `fail_on_tool_error`。

正式执行时把 `V2/监考提示词.md` 整段交给监考 AI。监考器从同版本试卷提取唯一 Agent 输入，创建
全新 WebSocket Session，并将证据写入 `V2/运行记录/<YYYYMMDD-HHMMSS>/`。被测 Agent 只允许在
实际 workspace 的 `evals/subagent-termination-recovery-v2/` 写交付物。

V2 同时覆盖：Linux/容器 executor、cooperative/force-killed/termination-failed、绝对 deadline
跨重启、finish/claim/delivery 幂等、由 Runtime 写出的 `tool_recovery`、Timeline 双端选择和 Payload 默认关闭。
任一硬门禁缺失均不能由其他项目得分抵消。
