# nanobot 子智能体终止与恢复综合试卷 V1

版本：2026-08-02

时限：前检 10 分钟；正式运行 30 分钟；终态稳定观察和归档 10 分钟。

## 一、评测对象

评测真实链路：

```text
Gateway -> AgentLoop -> Runner -> Tool/Subagent/Executor -> durable orchestration
        -> Audit emitter/indexer -> Graph/Events API -> dist -> Chromium
```

禁止以 mock、直接 seed lifecycle Event、线程池、`task.cancel()` 返回、发送 SIGKILL 请求或合成页面
冒充目标能力。Linux/容器关键场景不得 skip/xfail。

## 二、环境和安全门禁

开考前必须确认当前部署 commit、镜像 ID、实际 `8765` bundle、配置解析出的 workspace/audit root、
WebSocket、Audit index 和 Chromium 均可用。fixture 必须逐个校验 SHA-256。不得输出或归档 secret、
token、cookie、ticket、完整 prompt、Tool 参数/Payload、PID 对应命令行或用户文件内容。

PID 仅作当次诊断；kill 必须同时验证 executor ID、process instance identity、父 supervisor 身份和
启动证据。身份不匹配时必须拒绝 kill。Payload endpoint 在用户显式点击前请求数必须为 0。

## 三、唯一 Agent 输入

监考器必须结构化提取本节唯一 `text` 代码块，并逐字符发送到全新 WebSocket Session：

```text
/goal 运行子智能体终止与恢复 V1 场景。只使用本地资源，不访问网络。创建四个 required=true、task_group="termination-recovery-v1" 的子任务，label 分别为 cooperative-child、force-kill-tree、deadline-restart、tool-recovery；记录每个 spawn 返回的真实 task_id 和 child_run_id。cooperative-child 只用 exec 运行 `_other/评测/子智能体终止恢复/V1/fixtures/cooperative_child.py`。force-kill-tree 只用 exec 运行 `_other/评测/子智能体终止恢复/V1/fixtures/stubborn_tree.py`。deadline-restart 先用 exec 等待 90 秒再只返回 DEADLINE_RESTART_DONE。tool-recovery 必须先用 read_file 读取不存在的 `_other/评测/子智能体终止恢复/V1/fixtures/recovery-target/missing.json` 并保留该失败 tool_call_id，再显式以 recovery_of_tool_call_ids 关联该 ID，成功读取 `_other/评测/子智能体终止恢复/V1/fixtures/recovery-target/config.json`。使用 await_subagents 等待完整 task_group，不得把 timeout_seconds 用于延长 durable deadline。监考器会在执行中取消指定 child 并真实重启 Gateway；不得自行规避或重建任务。只有 barrier_satisfied=true 且四项真实终态均可解释后，才在 `evals/subagent-termination-recovery-v1/result.json` 写入标准 JSON，字段固定为 protocol、task_ids、child_run_ids、deadline_at、barrier_satisfied、delivery_count、notes；不得写 PID、secret、Payload 或完整 Tool 输出。无法满足时调用 update_goal(action="block") 并如实说明，不得伪造成功。最后只报告 Goal、四项 task、barrier 和交付文件状态。
```

## 四、监考场景

监考器必须执行以下场景；S05-S13 使用仓库正式真实重启 suite，不能在同一 Python 对象中模拟重启：

| ID | 场景 | 关键期望 |
|---|---|---|
| S01 | cooperative cancel | grace 内 root 退出；无 SIGKILL；`cooperatively_exited` |
| S02 | stubborn worker + descendant | TERM/KILL 进程组；root wait/reap；后代清理；`force_killed` |
| S03 | 注入 kill/reap 失败 | `termination_failed/lost`；required guard 拒绝成功 final |
| S04 | optional 强杀失败 | owner final 不阻塞；anomaly/通知各一次 |
| S05 | required 等待中重启 | 原 `deadline_at` 字符串不变，remaining 减少 |
| S06 | 重启前完成未 claim | 恢复后只 claim/deliver 一次 |
| S07 | 重启后才完成且不可重接 | 诚实 `lost`，不猜测成功 |
| S08 | 重启时 deadline 已过 | 不重新获得默认预算，立即终止流程 |
| S09 | durable state 损坏 | 保留原数据并 fail-closed |
| S10 | MessageBus 重复结果 | history/outbound/continuation 各至多一次 |
| S11 | startup recovery 两次 | 第二次幂等 no-op |
| S12 | claimed pending delivery 时崩溃 | 恢复后恰好一次 delivery |
| S13 | PID reuse/identity mismatch | 不误杀无关进程，任务 `lost` |
| S14 | Tool recovery API | 显式 ID、同 Trace/Run、双 terminal anchor、evidence count |
| S15 | WebUI 双端定位 | 侧边恢复边；失败/恢复 Event 行依次选中；原始 Event 可重复定位 |
