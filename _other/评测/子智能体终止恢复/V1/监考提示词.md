## 一、前检

完整阅读 `AGENTS.md`、`.agent/design.md`、`.agent/security.md`、试卷、相关 executor/subagent/
orchestration/Audit/WebUI 源码和正式 scenario suite。记录 `git status --short --branch`、HEAD、远端、
容器、镜像、health、8765 页面、实际 bundle、配置解析后的 workspace/audit root。不得 fetch upstream。

对试卷、监考提示词和三个 fixture 计算 SHA-256；结构化提取试卷第三节唯一 `text` 代码块，校验发送
前后字符、UTF-8 字节和 SHA-256 完全相同。关键 Gateway/WebSocket/Audit/Chromium 不可用时不发送，
结论为“评测环境不可执行”。缺少 killable executor 或正式重启 suite 是产品失败，不是环境失败。

## 二、开考与故障操作

通过真实 Chromium 打开 `http://127.0.0.1:8765/`，在 page 创建前注册 console、pageerror、
requestfailed、WebSocket close/error。bootstrap secret/token 只在内存使用并立即从 URL/展示层清除。
新建 Session，逐字符发送唯一输入。

从结构化 spawn 结果提取 task/child Run ID。按试卷 S01-S04 对相应受控 executor 执行取消和故障注入；
不得仅取消浏览器请求或主 asyncio Task。按仓库正式 scenario suite 执行 S05-S13，其中 Gateway/worker
必须真实停止和重启。只操作本场新建的容器/进程和经 identity 验证的 executor；不得依据持久化 PID
杀进程。每次操作记录 UTC、executor identity 摘要、请求、退出、reap、后代与 fd/pipe 清理结果。

如果仓库没有可执行的正式 suite 或安全故障注入点，将对应断言判 FAIL 并继续完成其他只读验收；禁止
临时修改产品、直接 seed Event 或用手工状态替代。

## 三、Audit/API 与浏览器验收

使用短期 bearer 分页收齐本场 Graph/Events，cursor 必须取自响应。不得调用 Payload endpoint，除非
试卷规定的最后显式 Payload 操作；记录该操作前请求数必须为 0。核验显式 recovery ID、同 Trace/Run、
terminal source/target、anchor、evidence count、revision 和 integrity；禁止按名称或时间推断。

在 1440x900 和 390x844 分别：打开真实 Trace；确认初始不预选 node；读取 recovery 与 sequence 的
`sourceHandle/targetHandle` 和 SVG `d`；点击恢复边；定位失败 Event 并断言对应 `[data-event-id]` 行选中；
定位恢复 Event 并断言选中切换；从双端 Node Inspector 原始 Event 再定位；检查因果链零命中解释、恢复
链路计数、not_found/cursor_stale/revision/limit 降级。console/page/request failed 必须全为 0。

## 四、测试与部署门禁

## 五、判分与归因

按 A01-A20 输出 `PASS|FAIL|UNKNOWN`，每项包含 endpoint/命令、字段路径、脱敏 evidence ID、观察值、
期望值、时间和归因。先归因：前检失败且未发送为环境不可执行；有产品缺失或独立失败证据为产品不通过；
基础证据损坏且无法区分才是证据不足；仅 20 项全 PASS、100 分且所有命令退出 0 才通过。

正式运行 30 分钟到时立即冻结判分，不取消或篡改仍运行任务。之后最多 10 分钟只读稳定观察，迟到结果
单列，不能改写硬时限结论。
