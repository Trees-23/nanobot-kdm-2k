# 审计运行轨迹更新清单与场景速记

[] a. 结构化错误语义：Tool、Model、Policy、Timeout、Cancelled、Exhausted 保留各自责任域；DuckDuckGo timeout 产生稳定且不泄密的摘要。场景：`web_search` 超时后，可确认是 Tool timeout，而不是笼统的 model error。

[] b. Run 致命影响：`RunFinished` 记录 `fatal_event_id/failure_policy/fail_on_tool_error`。场景：开启 `failOnToolError` 后，可精确定位是哪一个 Tool Event 终止 Run，而不是猜“最后一个错误”。

[] c. `recovery_of_tool_call_ids`：成功的 `ToolFinished` 显式指向同一 Run 中被它确定性纠正的失败 Tool Call。审计 Hook 使用不可逆资源指纹；目前 `read_file` 只有在规范资源相同，或绝对路径恰好增删一个中间目录时关联。场景：`recovery-target/runtime/config.json` 失败后读取 `recovery-target/config.json` 成功，可以判定恢复；读取 `unrelated/config.json` 即使同名也不能判定恢复。

[] d. 失败节点不改写：恢复只改变 `impact/recovery_status`，原失败 Tool 的终态仍是失败。场景：查看纠错后的首次 `read_file`，仍能看到当时真实失败，同时显示 `run_continued/recovered`。

[] e. 安全诊断：Graph 提供有界的 `error_type/error_code/error_summary/effective_timeout_ms/safe_input_summary`，服务端 allowlist、脱敏、限长并 fail closed。场景：看到 `File not found (path=...)`，但不会自动暴露文件内容、query、token 或堆栈。

[] f. “当前 Graph 未提供原始 Event 导航信息”修复：Graph 节点新增安全的 `raw_events` 回链，仅包含 Event ID、类型、时间、状态和 Payload ID。场景：从失败 Tool 节点定位到准确的 `ToolFinished`，再按需读取受保护 Payload；前端不是用 Event 重新构图，而是用 Event ID 返回证据层。

[] g. Payload 状态：区分 loading、success、truncated、metadata_only、401、404/过期、413 和 503；401 复用真实 `App.refreshReadyClient()` 认证入口且只重试一次。场景：登录过期时进入已有认证流程，不调用虚构的 `onReauth` API。

[] h. Event 有界定位：尚未加载的 Event 最多自动加载 5 页、1000 Event 或 10 秒，cursor stale 和达到上限都有提示。场景：从 Inspector 定位较早 Event 时不会无限翻页或静默失败。

[] i. 因果链：突出 `caused_by/retry/retry_of`。场景：选择路径读取失败节点，查看它由什么导致、哪个确定性纠错调用恢复了它。

[] j. 执行上下文：突出 `sequence`。场景：查看一次 Tool 调用之前的模型请求和之后的 Tool/模型步骤；执行先后不等于因果关系。

[] k. 结构分支：突出 `parent_run/spawn_branch`。场景：main Run 创建 child Agent 后，查看父子 Run 层级，判断错误属于 main 还是 child。

[] l. 恢复链路：突出 `result_return/resumed_from`。场景：查看 child 结果如何回流 main，或新 Run 从哪个旧 Run/检查点继续；单次 Tool 纠错通常属于因果链，而非这里的跨 Run 恢复。

[] m. 关系聚焦反馈：显示命中节点/边数量、零命中、清除动作，并在用户触发时 `fitView`。场景：选择一个没有 child 的普通 Tool 点击“结构分支”，应看到“零命中”，而不是误把选中节点算作结果。

[] n. 图工具栏：补齐“适配整张图”“定位 main Run”“定位首个异常”和可打开的键盘图例，并适配 reduced-motion。场景：定位异常时同时选中节点、聚焦因果关系并展示安全根因。

[] o. 时间线滚动：修复桌面时间线祖先缺少 flex 布局导致的不可滚动，增加 536 Event 真实浏览器 fixture。场景：普通、最大化、拖高和移动全屏均可到达 Event 1、200、201、536，分页后不跳顶。

[] p. 历史兼容：新字段均为 additive optional，不改写历史 Audit。场景：旧 Event 缺少结构化错误时保守显示 unknown/continued；升级后必须产生新 Run 才能完整看到新诊断字段。
