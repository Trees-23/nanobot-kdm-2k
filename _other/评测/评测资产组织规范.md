# nanobot 评测资产组织规范

本文是 `_other/评测/` 下新增和维护试卷、监考提示词、固定输入、运行产物与协议版本的统一入口。
以后生成评测材料前，先读取本文，再读取最接近的新旧主题作为模板。

## 一、基本目录

每项独立能力使用一个中文主题目录，禁止把试卷或提示词裸放在 `_other/评测/` 根目录：

```text
_other/评测/
├── 评测资产组织规范.md
└── <评测主题>/
    ├── 说明.md
    ├── V1/
    │   ├── 试卷.md
    │   ├── 监考提示词.md
    │   ├── fixtures/                 # 可选：固定、安全、可提交的输入
    │   └── 运行记录/<时间戳>/        # 执行时生成
    └── V2/                           # 协议变化时新增
```

主题目录使用稳定、简短、能表达能力边界的中文名，例如 `长任务编排`、`子智能体结果回流`、
`审计运行轨迹`。不要使用“临时”“新版”“最终版”“第一次考试”作为目录名。

根目录只保留本规范以及未来同级的全局索引或全局规范。任何属于单一主题的试卷、提示词、
fixture、更新说明和运行产物都必须进入对应主题，不能以“方便打开”为由裸放在根目录。

## 二、文件职责

| 文件或目录 | 内容 | 不应包含 |
|---|---|---|
| `说明.md` | 主题范围、目录结构、当前版本、版本差异、使用入口 | 某一次运行结果 |
| `Vn/试卷.md` | 被测能力、唯一输入、硬断言、评分和结论契约 | 监考器凭据、现场答案 |
| `Vn/监考提示词.md` | 给监考 AI 的前检、发送、观察、判分和归档指令 | 替 Agent 答题的内容 |
| `Vn/fixtures/` | 可重复、非敏感、版本固定的测试输入 | token、真实配置、生产数据 |
| `Vn/运行记录/<时间戳>/` | 本场前检、证据、截图、评分与风险 | 修改后的试卷、Audit 原始副本 |
| Agent workspace 交付目录 | 被测 Agent 按试卷生成的答案或文件 | 监考评分和权威试卷 |

需要保存“本版本改了什么、设计怎么理解、使用场景是什么”时，可增加 `Vn/更新清单.md`；它是
辅助说明，不替代 `试卷.md` 的权威断言。

## 三、版本规则

`Vn` 是评测协议版本，不是运行次数。出现以下任一变化时创建下一个版本：

[] a. 被测 Agent 的唯一输入发生语义变化。

[] b. 硬断言、分数、通过阈值或结论类型变化。

[] c. 权威 API、字段路径、证据来源或归因规则变化。

[] d. fixture 内容、目录或预期语义变化。

[] e. 安全边界、时间限制、允许工具或生成产物契约变化。

只修正排版、链接或错别字且不改变上述契约时，可修订当前版本。已经产生正式运行记录的旧版本
默认冻结；必须修正时创建新版本，并在主题 `说明.md` 写明迁移原因和差异。

## 四、命名规则

[] a. 固定入口使用 `说明.md`、`试卷.md`、`监考提示词.md`，不要为同一职责创造近义文件名。

[] b. 版本目录只使用大写 `V` 加连续整数，如 `V1`、`V2`。

[] c. 单次运行目录使用本地时间 `<YYYYMMDD-HHMMSS>`；结论明确后可追加简短中文后缀。

[] d. fixture 文件名表达数据角色，例如 `recovery-target/config.json`，不使用 `test1.json`。

[] e. Agent 交付目录写在试卷内，使用稳定 ASCII 路径；不得放入 `_other/评测/` 冒充监考证据。

## 五、生成流程

[] a. 先读 `AGENTS.md`、本规范、相近主题的 `说明.md/试卷.md/监考提示词.md` 和相关产品契约。

[] b. 建立 `<主题>/说明.md` 与首个 `V1/`，先明确能力边界、被测对象和权威证据。

[] c. 在 `试卷.md` 中固定唯一 Agent 输入、环境门禁、硬断言、评分/结论和安全要求。

[] d. 在 `监考提示词.md` 中引用同版本试卷，规定真实发送渠道、轮询、证据字段、归因和运行记录结构。

[] e. 需要固定输入时放入同版本 `fixtures/`，并在开考前校验存在性和 SHA-256。

[] f. 对路径、命令、代码符号和评分总和做静态检查；能自动运行的聚焦测试必须实际运行。

[] g. 用没有对话背景的读者视角回答：发什么、谁执行、如何判分、产物放哪、何时升版。任一答案不唯一就继续修订。

[] h. 正式执行只新增 `运行记录/<时间戳>/` 和试卷授权的 Agent 交付物，不改权威资产。

## 六、生成产物和运行记录

监考产物必须位于本版本：

```text
<主题>/Vn/运行记录/<YYYYMMDD-HHMMSS>/
```

建议至少包括 `前检.md`、`执行摘要.md`、结构化断言或评分 JSON、输入完整性、接口安全摘要、
控制台摘要和必要截图。具体文件以同版本试卷和监考提示词为准。

被测 Agent 生成的答案必须写入试卷指定的 Agent workspace 目录。权威 Audit 继续保存在 runtime
存储中，只通过受保护 API 读取安全证据；不得复制、裁剪或编辑 Audit JSONL 来制造评测材料。

## 七、提交前检查

[] a. `_other/评测/` 根目录除本规范外没有裸露的试卷、提示词、fixture 或运行结果。

[] b. 主题 `说明.md` 指向唯一当前版本，版本号和文件路径一致。

[] c. 试卷唯一输入可被结构化提取，监考提示词不重复维护另一份不同输入。

[] d. 分数加总、硬断言、通过阈值、时间限制和结论类型无矛盾。

[] e. fixture 不含 secret、个人数据、生产配置或不可提交的大文件。

[] f. 所有命令、相对路径和引用文件存在，`git diff --check` 通过。

[] g. 旧版本及其运行记录没有被原地改写。
