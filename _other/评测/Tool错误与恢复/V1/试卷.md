# Tool 错误与恢复评测试卷 V1

版本：2026-08-03

## 评测目标

验证通用 Tool 失败归一化和确定性恢复证据协议。满分 100 分；安全门禁失败、真实 Gateway 未启动、
Chromium 非真实运行或权威输入被修改时，本场不得计分。

## 固定输入与环境门禁

唯一运行输入是仓库中的 `webui/e2e/generate-audit-tool-recovery-runtime.py`。它必须通过真实
`AgentRunner`、`ReadFileTool` 和 `AuditRuntime` 生成新的 metadata-only Audit，再由真实 gateway
提供受保护 API 和已构建 WebUI。禁止手工编辑 Event、Graph 响应或浏览器 DOM。

开考前记录分支、commit、工作区状态、Python/Node/Bun/Chromium 可用性，并对生成器和 E2E 文件计算
SHA-256。临时配置、workspace、secret 和 bearer 只能位于临时目录或进程内，不得归档。

## 第一题：通用错误归一化（20 分）

| 评分点 | 判定标准 | 分值 |
|---|---|---:|
| 通用 fallback | 无专用错误码的失败仍有非空、安全、稳定的 type/code/message/summary/source/retryability | 5 |
| 精确错误 | Tool 提供的精确 type/code 不被 registry、hint 或 fail-on-tool-error 丢失 | 4 |
| 全入口 | validation、ToolResult、exception、timeout、cancel、policy、provider、runtime 均有测试 | 5 |
| 安全正文 | secret、控制字符和超长错误经过脱敏、标准化、截断；retry hint 不混入正文 | 4 |
| 旧数据 | 旧 Event 可读，UI 明示“历史版本未记录错误详情” | 2 |

## 第二题：Audit 模式与兼容（15 分）

| 评分点 | 判定标准 | 分值 |
|---|---|---:|
| metadata-only | Event 保留安全诊断，Payload 引用和内容均不存在 | 6 |
| full | 保持原有显式 Payload 边界，安全诊断仍在 Event | 4 |
| API 边界 | Graph 只返回安全诊断和关系元数据，不返回参数、结果、堆栈或 secret | 3 |
| 版本兼容 | builder 版本提升，旧 Event 和客户端字段保持 additive 兼容 | 2 |

## 第三题：恢复语义（30 分）

| 评分点 | 判定标准 | 分值 |
|---|---|---:|
| 状态全集 | 异常节点只使用 pending/recovered/continued/unrecovered/unresolved | 4 |
| retry | 重试单独建边，不等同 recovered | 4 |
| continuation | 同一 exec session/process identity 的后续动作建 continuation，运行中不算 recovered | 5 |
| recovery | 只有确定性状态验证产生 recovery，并保留失败节点终态 | 6 |
| 不相关成功 | 同 Tool、相邻或同 basename 的无关成功不误连 | 4 |
| fallback | 未知 MCP/plugin 和无 receipt 的 message 使用 unresolved，不伪造 recovery | 4 |
| 安全阻断 | policy blocked 默认为 non-retryable，不进入恢复集合 | 3 |

## 第四题：Tool inventory（10 分）

`_other/Tool错误与恢复Inventory.md` 必须覆盖注册 Tool，逐项说明错误来源、operation evidence 策略
和证据不足时的 fallback。filesystem、exec/write_stdin、spawn/subagent、Goal、web、message、cron、
MCP/CLI/plugin 和 image generation 均需有测试或明确 fallback。

## 第五题：真实 Graph 与 WebUI（20 分）

运行：

```bash
cd webui
bun run build
bunx playwright test e2e/audit-tool-recovery-real.spec.ts --project=chromium
```

| 评分点 | 判定标准 | 分值 |
|---|---|---:|
| 双视口 | 1440x900 和 390x844 均通过，无 console/page error | 4 |
| 错误详情 | 节点首屏展示安全错误正文、来源、可重试性和恢复状态，长文本可换行 | 4 |
| 三类关系 | retry、continuation、recovery 均可操作并打开对应检查器 | 5 |
| 双端定位 | recovery 检查器可精确定位失败端和后续端 Event | 4 |
| Payload 安全 | 页面未自动请求 `/api/audit/payloads/`，secret 不出现在 Graph/DOM/归档 | 3 |

## 第六题：回归质量（5 分）

指定 Python 聚焦测试、相关 `ruff check`、完整 `pytest`、完整 `bun run test` 和 `bun run build` 均
必须实际执行并如实归档。未执行不得写通过；既有失败必须给出精确归因。

## 结论契约

结论只能是：通过、有条件通过、实现不通过、评测环境不可执行、证据不足无法判定。达到 90 分且
第二、三、五题分别不低于其满分 80%，安全门禁无失败，才可判定“通过”。
