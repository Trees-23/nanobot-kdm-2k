# nanobot 审计运行轨迹连线与视觉层级重构实施方案

日期：2026-08-04

状态：待实施

指定实施分支：`codex/subagent-state-plan-v2`

现有 PR：<https://github.com/Trees-23/nanobot-kdm-2k/pull/11>

## 一、执行摘要

PR #11 已完成 Task 名称、结果回传语义、默认折叠、视口稳定和 Payload capture mode 等功能
修复，但真实用户验收确认当前跨泳道连线发生明显视觉回退：局部关系被强制绕到整图左右边缘，
形成超长折线、大面积空白和难以追踪的箭头；部分连线还会压过节点、区域标题和状态信息。

本方案只重构前端图的视觉层级、布局和边呈现，不回退已经验证的 Audit/Event/Graph/API 契约，
不改变任何 edge 的 ID、source、target、anchor、evidence 或方向。

核心决定如下：

1. 废止“所有跨泳道关系都走全局左右公共轨道”的方案；
2. 默认图只持续显示执行结构骨架，次要关系按选择、悬停或聚焦模式展示；
3. 使用仓库已有 `elkjs` 在 Worker 中联合计算节点位置和边折点；
4. 使用固定端口语义、局部正交路径和边捆绑，限制折点、绕行和交叉；
5. 节点和区域标题属于画布障碍物，状态控件和固定工具栏分别通过端口安全区与 viewport padding
   保护；
6. 初始适配以可读节点主体为准，异常远路由不得把全图缩成缩略图；
7. 几何自动化和人工截图审查共同构成完成条件。

## 二、问题与根因

### 2.1 用户可见问题

真实三子 Agent 并发 Trace 中已确认：

- 大量关系从节点出发后先飞到整张图最左或最右，再跨越很长距离折返；
- 同一局部关系的线长远大于两个端点之间的实际距离；
- 多条高饱和边同时出现，无法快速辨认来源、目标和方向；
- 箭头在缩放后过小，颜色和虚线不足以承担全部语义；
- 连线贴着或压过节点卡片、区域标题和状态徽章；
- 为容纳外侧轨道，初始 `fitBounds` 把节点缩得很小，并展示大量无意义空白；
- 用户必须先读图例再猜线，不能在画布上直接理解“分支、执行、结果”。

这不是单纯的 CSS 美观问题，而是信息层级和路由目标函数错误。

### 2.2 当前实现根因

主要实现位于：

```text
webui/src/components/traces/TraceGraph.tsx
webui/src/components/traces/toolRelationRouting.ts
webui/src/workers/auditLayout.worker.ts
webui/src/components/traces/nodes/TraceNode.tsx
```

已确认事实：

- `auditLayout.worker.ts` 只按固定 `LANE_PITCH=408`、`ROW_PITCH=136` 排节点，不参与边路由；
- `buildRelationRoutes()` 把所有 routed relation 放到 `visibleLeft - gap` 或
  `visibleRight + gap` 的全局外轨；
- 重叠区间通过增加 slot 继续向画布外侧扩展；
- 任一水平入口受阻时，`corridorY()` 会在全部节点的最上方或最下方选择走廊；
- `routeNodeBounds` 主动排除了 region node，区域标题和容器不是路由障碍；
- routed relation 使用 `zIndex=3`，语义节点使用 `zIndex=2`，边可能显示在卡片上层；
- 所有关系默认同时进入 `visibleGraphEdges`，没有默认可见性策略；
- `graphRouteBounds` 合并全部 relation route bounds，并参与自动 `fitBounds`；
- source/target 只使用左右中点 handle，不区分结构、执行、回传和恢复端口。

上一版方案中的以下决定被本方案明确废止：

```text
根据 lane_side 使用左/右全局公共轨道；
重叠区间为每条边分配不断向外扩展的 slot；
优先扩展自研 router，不使用已有自动布局引擎。
```

### 2.3 为什么旧验收没有发现

旧验收主要证明：

- 路径为正交线段；
- 线段与非端点语义 node bounds 保持 clearance；
- 输入 edge 顺序变化不影响 slot；
- 展开和收起后路径重新计算。

这些断言没有衡量：

- 总线长和端点距离的比例；
- 折点数量；
- 边与边的交叉、重叠和视觉捆绑；
- 区域标题、徽章、工具栏等非语义节点障碍；
- 箭头与端点在真实缩放下是否可辨认；
- route bounds 是否迫使初始视口过度缩小；
- 用户能否在不依赖图例的情况下追踪一条关系。

因此“几何无碰撞”被错误地当成“图可读”。新验收必须同时衡量正确性、紧凑性和可解释性。

## 三、参考产品与技术结论

### 3.1 运行轨迹产品

Jaeger、Phoenix 等 Trace 产品默认使用可折叠层级树和时间条承载完整执行历史。它们不会把每种
关系长期同时显示成高饱和连线：

- Jaeger `TraceTimelineViewer` 使用可折叠 Span 列表、时间列、虚拟化和详情侧栏；
- Phoenix `TraceTree` 使用 Span tree、缩进、选择态和 timeline bar；
- Temporal 只在 Workflow family 关系视图中画简化树，同一父节点的孩子共享短横向母线，并提供
  展开/收起；完整事件仍由详情和 Event History 承载。

参考：

- <https://github.com/jaegertracing/jaeger-ui/blob/master/packages/jaeger-ui/src/components/TracePage/TraceTimelineViewer/index.tsx>
- <https://github.com/Arize-ai/phoenix/blob/main/app/src/components/trace/TraceTree.tsx>
- <https://github.com/temporalio/ui/blob/main/src/lib/components/workflow/relationships/workflow-family-node-tree.svelte>

本轮不复制一套新的 Jaeger 时间线，也不删除现有 Graph。借鉴点是：默认视图承担主要结构，完整
证据放在选择、详情、Timeline 和关系聚焦中逐步展示。

### 3.2 React Flow 与 ELK

React Flow 不提供自动布局算法。其官方指南把节点布局和边路由视为独立能力，并列出 ELK 为同时
支持动态节点、子图和 edge routing 的完整方案：

- <https://reactflow.dev/learn/layouting/layouting>
- <https://reactflow.dev/examples/layout/elkjs>

ELK Layered 支持：

- 分层有向图；
- `ORTHOGONAL`、`POLYLINE` 和 `SPLINES` 路由；
- 固定端口侧、端口顺序和端口位置；
- crossing minimization；
- compound graph 和 cross-hierarchy edge；
- 节点与边间距；
- edge bend points 输出。

参考：

- <https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html>
- <https://eclipse.dev/elk/reference/options/org-eclipse-elk-edgeRouting.html>
- <https://eclipse.dev/elk/reference/options/org-eclipse-elk-portConstraints.html>
- <https://eclipse.dev/elk/reference/options/org-eclipse-elk-spacing-edgeNode.html>

仓库已经声明 `elkjs ^0.12.0`，但当前审计图未使用它。因此本方案不新增布局依赖，而是启用已有
依赖并保留 Worker 隔离，避免在 React 主线程同步计算大图布局。

## 四、冻结的产品决定

以下决定在实施时不得重新改回全局外轨。只有真实代码或性能证据证明不可行时才允许调整，并必须在
PR 正文记录原因和替代方案。

### D1 默认只持续显示执行结构骨架

边按默认可见性分为三层：

| 层级 | Edge type | 默认行为 |
|---|---|---|
| 主骨架 | `sequence` | 始终显示，细、低对比，只连接泳道内相邻执行节点 |
| 主骨架 | `spawn_branch` | 始终显示，连接 Spawn Tool -> Task |
| 主骨架 | `task_execution` | 始终显示，连接 Task -> Child Run |
| 按需关系 | `result_return` | 默认用 Task/目标节点的“结果已回传”标记提示；选中、悬停或结果聚焦时显示完整边 |
| 异常关系 | `retry`、`retry_of`、`tool_retry` | 有异常时显示短提示；选择端点或重试聚焦时显示完整边 |
| 恢复关系 | `resumed_from`、`tool_recovery`、`task_recovery` | 端点显示恢复状态；选择端点或恢复聚焦时显示完整边 |
| 结构例外 | `task_replacement`、`tool_continuation`、`parent_run`、`caused_by` | 按语义在选择/聚焦时显示；首个异常定位可主动打开相应关系 |

要求：

- 隐藏默认边只改变表现，不删除 Graph 数据，也不改变 Inspector 和关系计数；
- 关系工具栏显示各类关系数量，例如“结果 3”“恢复 1”；
- 用户点击某个 Task、Child Run 或关系标记时，相关边立即出现且其他边降低透明度；
- 没有命中的聚焦模式继续显示明确空状态；
- 移动端不长期渲染全量次要关系，使用关系列表或选择后单条定位。

### D2 使用局部、方向明确的固定端口

不同关系不得共用节点左右中点造成视觉贯穿。至少定义：

| 关系 | source port | target port | 主要方向 |
|---|---|---|---|
| `sequence` | bottom | top | 同泳道自上而下 |
| `spawn_branch` | 面向 Task 泳道的一侧 | 面向 Spawn 的一侧或 top | Spawn -> Task |
| `task_execution` | bottom 或面向 Child 的一侧 | top 或面向 Task 的一侧 | Task -> Child Run |
| `result_return` | 面向注入位置的一侧独立 result port | 面向 Task 的独立 input port | Task -> injection/continuation |
| retry/recovery | 独立 recovery port | 独立 recovery port | 旧执行 -> 新执行 |

端口规则：

- 使用 ELK port constraints 固定 side/order；
- 同一节点的 incoming、outgoing、result、recovery 不得落在同一坐标；
- 箭头必须在目标端点外侧清晰可见，不压住卡片或状态文本；
- 端口仅在 hover、selection 或键盘 focus 时增强显示，默认保持克制；
- 端口和边必须有可访问名称。

### D3 ELK 联合计算节点和边

`auditLayout.worker.ts` 改为真正的布局 Worker，输入可见节点、region/lane、边及端口约束，输出：

```text
node positions
region/lane bounds
edge sections
bend points
layout bounds
warning/fallback reason
```

推荐基线配置：

```text
algorithm = layered
direction = DOWN
edgeRouting = ORTHOGONAL
hierarchyHandling = INCLUDE_CHILDREN（仅在 compound lane 方案验证可行后启用）
portConstraints = FIXED_ORDER 或 FIXED_SIDE
```

具体 option key 以 `elkjs 0.12` 实际类型和运行结果为准，不得把未经验证的字符串直接散落在多个
组件中。配置集中在 Worker 的一个可测试构造函数中。

布局必须保护：

- main lane 的稳定中心位置；
- child lane 的左右顺序和 `lane_order`；
- lane 内 `node.order` 的时间顺序；
- 折叠节点和展开节点的身份稳定；
- 同一节点集合重复布局得到相同结果；
- 输入数组顺序变化不改变语义顺序和端口分配。

如果 ELK 无法直接满足固定泳道顺序，允许采用两阶段布局：先确定 lane/region 框架，再让 ELK 在
局部容器内排节点和计算跨容器边；不得回退到整图左右外轨。

### D4 局部路由优先，边捆绑只用于共同父级

- 路径只能在 source/target 所在 lane 及其相邻通道内寻找，不得无条件绕到全图边界；
- 同一 Spawn 或同一父 Task 的多个结构分支可以共享一段短母线，参考 Temporal family tree；
- 不同语义的边不能捆绑成无法区分的一条线；
- 边分叉后必须能沿箭头追踪到唯一目标；
- ELK 输出不满足可读性阈值时，优先切换该边为局部 SmoothStep/短正交 fallback；
- fallback 必须记录可测试的 reason，不得静默使用旧全局 rail。

### D5 视觉障碍和图层完整

需要保护的画布世界坐标 bounds 包括：

- Trace semantic node；
- collapse group；
- region/lane header；

状态徽章和展开按钮位于 semantic node 内，端口必须避开它们占用的内容安全区。固定工具栏、关系
选择器和反馈浮层属于屏幕坐标覆盖层，不送入 ELK；通过 React Flow viewport padding 和首屏可见区
inset 保证节点、箭头和边标签不被其遮挡。

边图层规则：

- 普通边始终位于节点卡片和区域标题下方；
- selected edge 可以提高颜色、宽度和 glow，但仍不得覆盖卡片内容；
- 不使用大面积发光、动画流光或多色渐变；
- 主骨架使用中性灰和一种结构强调色；
- 结果、恢复、重试仅在激活时使用蓝、青、琥珀等语义色；
- 颜色不是唯一信号，必须同时使用线型、箭头、短标签或状态标记。

### D6 关系必须可以就地识别

- 激活边在首个稳定水平段或中点显示短标签：“分支”“执行”“结果”“恢复”“重试”；
- 标签使用不遮挡路径的紧凑背景，并纳入碰撞检查；
- hover/focus 一条边时高亮 source、target、完整路径和短标签；
- 其他节点和边降到约 10%-20% opacity，但端点不可被一起变暗；
- 点击边继续打开准确的关系 Inspector；
- 键盘用户能够按 Tab 聚焦关系标记或通过关系列表选择，不能要求精确点中 1px SVG 线。

### D7 初始视口不由异常路由支配

- 首次自动 fit 以 node/region 主体 bounds 为主，并包含正常局部结构边；
- 按需隐藏的 result/recovery/retry edge 不进入初始 fit bounds；
- route bounds 超出 node bounds 的比例超过阈值时，不得继续缩小整图；
- 用户显式选择关系后可以平滑定位该关系，但普通选择仍保持现有 viewport 稳定语义；
- “适配整张图”需要区分“适配执行结构”和“适配当前可见关系”，默认执行前者；
- `minZoom=0.035` 不能成为正常三子任务 Trace 的实际首屏缩放目标。

### D8 不改变后端审计证据和已完成修复

必须保留：

- lifecycle optional `task_label` 和旧事件 `Task <ID>` fallback；
- Task 标题使用任务名称，Inspector 单独显示 Task ID；
- `result_return` 与 recovery/retry 的准确语义分类；
- 单次成功 attempt 和成功链默认折叠；
- 节点点击、Inspector、Timeline 和 Payload 不自动 fit；
- additive optional `audit_mode` 和 `metadata_only` 提示；
- Graph/Events list 不嵌入 Payload content；
- 后端 edge source、target、anchor、evidence 和 direction。

除非前端所需字段确实缺失，不修改 Python Audit schema、Graph builder 或 read service。若必须增加
字段，只允许 additive optional safe summary，并需要 Python 契约和脱敏测试。

- 1366x768、1440x900、1920x1080、390x844；
- 100%、125%、150% 浏览器缩放。

建议提交：`测试（运行轨迹）：验证ELK连线与渐进关系交互`

## 六、量化验收标准

### 6.1 默认结构图

- 三子 Agent Trace 默认不存在到整图最左/最右边界的外绕线；
- `spawn_branch` 和 `task_execution` 能逐段追踪到唯一端点；
- 默认不同时显示全部 result/retry/recovery 长边；
- 结构边 route bounds 不得让节点主体占可视区域宽度低于 55%；
- 1440x900 首屏的关键 Task 标题和状态无需放大即可辨认；
- 任何普通边不覆盖卡片、区域标题、徽章、展开按钮或工具栏。

### 6.2 路由质量

对每条当前可见的非 `sequence` 边计算：

```text
manhattan_distance = abs(source_port.x - target_port.x) + abs(source_port.y - target_port.y)
route_length = 所有 path segment 长度之和
detour_ratio = route_length / max(manhattan_distance, 1)
```

要求：

- 普通局部结构边最多 3 个 bend；
- 普通局部结构边 `detour_ratio <= 1.6`；
- 复杂 recovery/replacement 边最多 5 个 bend，`detour_ratio <= 2.2`；
- 超过阈值必须给出明确 fallback/diagnostic，不能静默通过；
- 所有非端点画布 bounds 保持至少 12px 图坐标 clearance，并在实际 viewport transform 下保持至少
  2px 屏幕 clearance；
- edge-edge crossing 数量相较旧基线显著下降，结构骨架目标为 0；
- 相同输入重复布局和输入数组乱序后，节点顺序及路径拓扑保持稳定。

阈值可根据真实 ELK 输出小幅调整，但调整必须先附真实截图和统计，不得为了让测试变绿而无依据
放宽。

### 6.3 交互可读性

- hover/focus/选择关系时，完整路径、source、target 和短标签同时高亮；
- 非相关边 opacity 降低，端点保持可读；
- `result_return` 激活后显示“结果”，方向和 Inspector 文案一致；
- 关系选择不改变后端 edge，也不伪造新 edge；
- 点击节点、打开/关闭 Inspector、Timeline、Payload 前后 viewport transform 不变；
- 用户显式定位关系时允许移动视口，并可清除聚焦返回原结构图。

### 6.4 人工视觉审查

截图不是可选项。完成前必须由实施 AI 查看原始尺寸截图并逐张记录：

- 是否能在 3 秒内指出一条结构边的 source 和 target；
- 是否存在超长无意义空白；
- 是否存在连线压过“人脸”，即卡片标题、正文、状态和 region header；
- 不看图例是否能理解当前激活关系；
- 缩放后箭头和短标签是否仍能辨认；
- 展开/收起前后图是否保持视觉连续性。

不得仅凭 Playwright 断言或“截图已生成”宣称视觉通过。
