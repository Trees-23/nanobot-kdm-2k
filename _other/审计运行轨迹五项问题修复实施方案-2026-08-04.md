# nanobot 审计运行轨迹五项问题修复实施方案

日期：2026-08-04

状态：待实施

指定实施分支：`codex/subagent-state-plan-v2`

现有 PR：<https://github.com/Trees-23/nanobot-kdm-2k/pull/11>

## 一、目标与范围

本方案修复子 Agent 审计运行轨迹中的五个已确认问题：

1. 跨泳道连线拥挤、重叠、穿越节点，图难以阅读；
2. Task 节点显示 `Task 96320128` 等内部 ID，而不是任务名称；
3. 正常的子 Agent 结果回传被归入“恢复链路”，检查器使用“失败端”等错误文案；
4. `metadata_only` 模式下 Payload 按钮全部消失，但页面没有解释原因；
5. 点击节点后，画布因检查器打开和自动 `fitBounds` 被缩到很小。

本方案是现有“统一子 Agent 任务状态机与主子 Agent 协同闭环”的收口工作，不重新实现
TaskStore、Goal barrier、子进程执行器或 Audit Graph。不得修改历史 Audit JSONL，不得用前端
字符串猜测弥补缺失的审计契约。

## 二、已确认事实

### 2.1 真实样本

```text
Session: websocket:37ebb144-e480-4baa-af86-f4b401747a30
Trace: 019fc842-5904-7bca-a517-23177b0e01dc
Main Run: 019fc842-5904-7847-967d-a7317d7c85a9
Task: 96320128
Task label: 检查一级目录
Child Run: 019fc842-af05-76d4-86d0-f7a3929b8635
Task group: goal-parallel-demo
```

该 Task 已完整经历 created、queued、running、awaiting_tools、tools_completed、final_response、
terminal succeeded、result ready 和 delivered。它不是恢复任务。

样本 Graph 包含 180 个 Event、53 个节点、55 条边，其中有 46 条 `sequence`、13 个
`model_attempt`、3 条 `spawn_branch`、3 条 `task_execution` 和 3 条 `result_return`。

### 2.2 连线路由现状

- `auditLayout.worker.ts` 使用固定 `LANE_PITCH=356`、`ROW_PITCH=116`；节点尺寸为
  248x76，横向净空约 108px，纵向净空约 40px。
- `toolRelationRouting.ts` 只处理 `edge.type.startsWith("tool_")` 的边。
- `spawn_branch`、`task_execution`、`result_return` 等跨泳道边继续使用通用 SmoothStep，
  没有节点避障或独立 slot。
- 当前样本没有 `tool_*` 关系，所以已有专用避障路由在该图中完全未参与。
- Graph 已生成成功链 `collapse_groups`，但 WebUI 用空集合初始化 `collapsedGroups`，默认不折叠。
- `_trace_full_nodes()` 把每个 model attempt expansion 强制改为 `default_expanded=True`，即使只有
  一次成功尝试，也会显示重复层级。

### 2.3 Task 名称现状

`SubagentTask` 持久化记录已有 `label="检查一级目录"`。但是：

- 子 Agent lifecycle Audit schema 没有 `task_label`；
- `SubagentLifecyclePublisher` 没有把 `task.label` 写入 Event；
- `AuditGraphBuilder` 只能硬编码 `label=f"Task {task_id[:12]}"`；
- WebUI 只是正确渲染后端返回的 `node.label`，不是名称丢失的源头。

### 2.4 结果回传语义现状

`input_injected(injection_source="subagent_result")` 被正确投影为 `Subagent result`，对应边为
`result_return`。问题在前端：

- `result_return` 被放入 `resume` 聚焦模式；
- `resume` 同时包含真正的 `resumed_from`、Tool recovery 和 Task recovery；
- 所有选中边共用“恢复关系检查器”“失败端”“后续端”等文案。

因此后端证据没有把成功结果伪造成恢复，错误发生在前端关系分类和呈现。

### 2.5 Payload 现状

样本预览配置使用：

```json
{
  "audit": {
    "mode": "metadata_only"
  }
}
```

`AuditEmitter` 在该模式下会主动丢弃 Payload，Event 的 `payload_id` 因此为 `null`。时间线只在
`payload_id` 存在时渲染按钮。旧轨迹无法事后补回 Payload。

配置 schema 默认值虽然是 `full`，但 WebUI 的 sessions/graph 状态没有公开当前 capture mode，
用户无法判断是“事件本来没有 Payload”还是“实例处于 metadata_only”。

### 2.6 点击后缩放现状

- 宽屏选择节点后，`TraceWorkbench` 增加固定 380px 的第三列检查器，画布宽度立即变小。
- `selectedNodeId` 进入 `renderNodes` 依赖，进一步影响 `visibleNodeBounds` 和
  `graphRouteBounds`。
- `graphRouteBounds` 变化后 effect 无条件调用 `fitBounds`。
- 因此纯选择状态也会触发布局适配；节点多时缩放可接近 `minZoom=0.035`。

## 三、冻结的设计决定

以下决定用于避免实施阶段重复询问。只有代码事实证明不可行时才允许调整，并必须在 PR 中记录原因。

### D1 Task 名称使用向后兼容的审计字段

- lifecycle Event 新增可选 `task_label`，由 `SubagentLifecyclePublisher` 从 `SubagentTask.label`
  写入。
- Graph Task node 和 Task region 优先显示 `task_label`。
- `task_id` 继续作为稳定标识，在 Inspector 中单独展示，不拼进主标题。
- 旧 Audit 没有 `task_label` 时降级为 `Task <ID>`，不得读取当前 TaskStore 给历史记录补名，避免
  Audit 回放依赖可变业务状态。
- 建议在 `AuditNodeSummary` 增加可选 `task_label`，前端类型保持 additive optional。

### D2 关系分类拆分“结果”与“恢复”

- `result_return` 属于“结果回传”，不属于“恢复链路”。
- `resumed_from`、`tool_recovery`、`task_recovery` 属于恢复。
- `tool_retry` 属于重试，`tool_continuation` 属于继续，不与成功结果回传混为一谈。
- `TraceFocusMode` 增加或改造为独立的 result/recovery 语义；中文显示必须准确。
- 关系检查器采用按 edge type 配置的标题和字段名，不再对所有边显示“失败端”。

建议字段：

| Edge | 标题 | 来源字段 | 目标字段 |
|---|---|---|---|
| `result_return` | 结果回传 | 结果来源 | 注入位置 |
| `spawn_branch` | 子任务分支 | 发起位置 | 子执行位置 |
| `task_execution` | Task 执行 | Task | Child Run |
| `task_replacement` | Task 替换 | 原 Task | 替代 Task |
| `resumed_from`/recovery | 恢复关系 | 原执行/失败端 | 恢复端 |
| retry | 重试关系 | 原尝试 | 重试尝试 |

### D3 先降低默认复杂度，再增加适量间距

只加间距会扩大整图边界，并在自动适配时让节点更小。必须组合实施：

1. 单次成功的 `model_attempt` 默认收起；失败、多尝试或异常时默认展开；
2. 后端已声明的成功链默认折叠，用户可显式展开；
3. 泳道间距提高到约 400-420px，行距提高到约 132-140px；
4. 使用稳定的响应式常量，不按 viewport 宽度动态缩放字体或节点；
5. 折叠后仍保留 Task、Child Run、结果回传和异常端点，不隐藏审计主链。

对当前样本，隐藏 13 个单次成功 attempt，并将 3 组共 9 个成功节点替换为 3 个折叠节点后，
预计可见节点从 53 个降至约 34 个。

### D4 跨泳道边使用统一正交避障路由

- 泳道内 `sequence` 保持简洁、低视觉权重，不送入外部公共轨道。
- `spawn_branch`、`task_execution`、`result_return`、Task replacement/recovery 和现有
  `tool_*` 接入统一的 relation router。
- 根据目标 child lane 的 `lane_side` 选择左侧或右侧公共轨道。
- 垂直区间重叠的边分配确定性 slot；排序不得依赖输入数组顺序。
- 路由的每个水平/垂直 segment 必须避开非端点节点边界和固定 clearance。
- spawn 和 result 可以共用路由算法，但必须保留不同颜色、虚线和箭头方向。
- 不引入重量级自动布局依赖；优先扩展现有 `toolRelationRouting.ts`，并重命名为更通用的职责名称。

### D5 节点选择不改变图拓扑或自动缩放

- 节点 `selected`、dimmed、status style 等纯展示状态不得参与几何边界依赖。
- 自动 fit 只允许发生在首次布局、节点集合变化、折叠/展开或用户显式点击“适配整张图”时。
- 普通节点点击、打开/关闭 Inspector、加载 Timeline 或 Payload 不得自动 fit。
- 宽屏 Inspector 优先改为覆盖式右侧 Sheet/overlay，保持 Graph 容器宽度稳定；若保留第三列，必须
  保存 viewport transform，并在 resize 后保持 zoom/center，不得重新 fit 整图。
- 用户显式执行“定位 main Run”“定位异常”“聚焦关系”时允许改变视口。

### D6 Payload 模式必须透明，但不放宽安全边界

- API 的 audit index/session/graph 状态增加 additive 的 `audit_mode` 或等价 capture mode 字段。
- WebUI 在 `metadata_only` 时显示一次明确状态：“当前仅记录事件元数据，不保存 Payload”。
- 无 `payload_id` 的 Event 不创建虚假按钮；`full` 模式也不承诺每个 Event 都有 Payload。
- 要验证 Payload，测试/预览实例可改为 `full` 并重启 Gateway，只验证新生成的轨迹。
- 不提交临时配置、bootstrap secret、Audit runtime、完整 prompt、完整工具参数或其他敏感数据。
- 不建议自动把生产实例切换为 `full`；由部署者根据隐私和存储策略选择。

## 六、兼容、安全与回退

- `task_label` 必须 optional，旧 Event 和旧索引可继续读取。
- 不从 TaskStore 回填历史 Graph，以保持 Audit 可独立重建。
- 不修改 edge 的证据 ID、source/target 或方向，只改变前端分类和路由几何。
- 不把 Payload 嵌入 Graph、Event list 或 WebSocket task DTO。
- `full` 模式可能记录经脱敏的 prompt、工具输入和输出；只在明确的测试/部署配置中启用。
- 若新路由无法为极端图找到无碰撞路径，应降级到可解释的外侧轨道并记录测试，不得静默画穿节点。
- 若 Inspector overlay 影响可访问性，保留现有 Sheet 语义和焦点管理，再调整视觉定位。
- 不引入新的状态模型、Graph relation type 或持久化存储，除非现有类型无法表达且有测试证明。

## 七、交付纪律

- 全部改动继续位于 `codex/subagent-state-plan-v2`，不得创建新分支或 worktree。
- 开始前确认工作区没有用户未提交修改；若有，保护并报告，不得 stash/reset/clean。
- 每个工作单元验证后创建中文提交并立即推送当前分支。
- 只暂存明确路径，不使用 `git add .` 或 `git add -A`。
- 持续维护 PR #11，正文更新改动内容、验证结果、协议兼容和风险。
- 未经用户针对 PR #11 的明确确认，不得合并 `main`。
- 最终报告分支、全部提交、推送结果、PR 状态、测试和真实浏览器证据。

## 八、完成定义

只有同时满足以下条件才可宣称完成：

- Task 名称来自持久化审计证据，旧轨迹兼容；
- 正常结果回传不再显示为恢复或失败；
- 默认图复杂度下降，关键跨泳道边经过确定性避障路由；
- 点击节点不改变 viewport zoom；
- Payload capture mode 对用户可见且不放宽安全边界；
- 聚焦 Python、WebUI、build 和真实 Playwright 验收全部通过；
- 所有提交已推送到现有分支并进入 PR #11，但尚未合并 `main`。
