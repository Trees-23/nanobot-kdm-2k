## 二、必须解决的问题

### 1. Task 显示任务名称

当前持久化 `SubagentTask` 已有 `label`，但 lifecycle Audit Event 没有名称，Graph 因此硬编码
`Task <ID>`。

必须实现：

- lifecycle Event 增加 optional additive `task_label`；
- Publisher 从 `SubagentTask.label` 写入；
- Graph Task node/region 优先显示名称；
- Inspector 单独保留 Task ID；
- 旧 Event 缺少名称时降级显示 `Task <ID>`；
- 不允许 Graph 查询当前 TaskStore 给旧 Audit 回填名称。

### 2. 分离结果回传与恢复语义

`result_return` 表示子 Agent 成功结果进入主 Agent 上下文，不是断线恢复、失败恢复或重试。

必须实现：

- 从“恢复链路”中移出 `result_return`；
- 为结果回传提供独立聚焦/显示语义；
- 按 edge type 定义检查器标题、来源字段和目标字段；
- `result_return` 使用“结果来源/注入位置”，不得显示“失败端”；
- 真正的 retry、continuation、recovery 和 resumed_from 继续准确呈现；
- 不修改后端真实 edge source、target、anchor 和 evidence。

### 3. 整理节点与跨泳道连线

当前真实样本有 180 Event、53 节点、55 条边；现有避障路由只处理 `tool_*`，对该样本完全
没有生效。

必须实现：

- 单次成功 model attempt 默认收起；失败、多次尝试或异常默认展开；
- 后端声明的成功链默认折叠并可显式展开；
- 适度增大稳定泳道/行间距，但不得只靠放大间距；
- 将 `spawn_branch`、`task_execution`、`result_return`、Task replacement/recovery 和
  `tool_*` 接入统一正交避障路由；
- 根据 `lane_side` 使用左/右公共轨道；
- 重叠垂直区间分配确定性 slot；
- 非端点节点必须保留 clearance，输入边顺序变化不得改变路由；
- 泳道内 `sequence` 保持低权重简洁连接；
- 保留不同 relation 的颜色、虚线和箭头方向。

优先扩展现有路由算法，不引入重量级布局依赖。若重命名文件，必须在同一提交更新所有引用和测试，
不得混入无关重构。

### 4. 点击节点后保持视口稳定

当前 `selectedNodeId` 会间接改变 `graphRouteBounds` 并触发 `fitBounds`，宽屏 Inspector 还会压缩
画布宽度。

必须实现：

- selected/dimmed/style 等纯展示状态不参与几何边界依赖；
- 普通节点点击、Inspector 开关、Timeline/Payload 开关不得调用自动 fit；
- 首次布局、节点集合变化、折叠/展开和用户显式“适配整张图”仍可 fit；
- 桌面 Inspector 优先使用不改变 Graph 容器宽度的 overlay/Sheet；若保留第三列，必须保持原
  viewport zoom/center；
- 用户显式“定位 main Run”“定位异常”“聚焦关系”仍允许改变视口。

### 5. 解释 Payload capture mode

样本环境是 `audit.mode=metadata_only`，该模式不会写 Payload，旧轨迹也不能恢复。

必须实现：

- audit API 状态以 additive optional 字段公开 `audit_mode` 或等价 capture mode；
- WebUI 在 `metadata_only` 时明确提示“当前仅记录事件元数据，不保存 Payload”；
- 不给 `payload_id=null` 的 Event 制造虚假 Payload 按钮；
- `full` 模式也不承诺每个 Event 都有 Payload；
- Graph/events 列表不得嵌入 Payload content；
- 不自动修改用户生产配置，不提交测试 secret、临时 Audit 或 runtime 数据。

真实验收时，可以对隔离的预览配置启用 `full`，重启 Gateway，并只验证新生成的轨迹。
