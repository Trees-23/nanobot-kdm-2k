## 四、必须实施的产品行为

### 1. 默认关系分层

默认持续显示：

```text
sequence
spawn_branch
task_execution
```

默认不画完整长边、但必须提供节点状态标记和关系计数：

```text
result_return
retry / retry_of / tool_retry
resumed_from / tool_recovery / task_recovery
task_replacement / tool_continuation / parent_run / caused_by
```

当用户选中端点、悬停关系标记或进入对应 focus mode 时，再显示完整关系边。隐藏只影响表现，
不得从 Graph 数据中删除边，也不得让 Inspector、计数、深链接或键盘操作失效。

### 2. 删除全局外轨

必须删除或停止使用以下默认路由思想：

```text
visibleLeft - railGap - slot * slotGap
visibleRight + railGap + slot * slotGap
所有障碍物顶部/底部的全局 corridorY
```

任何局部关系不得无条件飞到整图边缘。ELK 失败时使用局部短正交或 SmoothStep fallback，并暴露
fallback reason；严禁静默回到旧全局 rail。

### 3. 使用已有 elkjs

仓库已经依赖 `elkjs ^0.12.0`。在 `auditLayout.worker.ts` 中接入 ELK Layered，联合输出节点位置、
region/lane bounds、edge sections、bend points 和 layout bounds。

优先验证：

```text
algorithm = layered
direction = DOWN
edgeRouting = ORTHOGONAL
portConstraints = FIXED_ORDER 或 FIXED_SIDE
```

需要 compound lane 时验证 `hierarchyHandling=INCLUDE_CHILDREN`。所有 option 集中定义并测试，不得
把魔法字符串分散在 React 组件中。

布局必须保持：

- main lane 中心稳定；
- child lane 左右顺序和 `lane_order`；
- lane 内 `node.order`；
- 折叠/展开节点身份；
- 重复布局和输入乱序后的确定性。

如果单次 compound layout 无法稳定保持泳道，采用“固定 lane 框架 + ELK 局部布局/跨容器路由”
两阶段方案。不得为了使用 ELK 而接受新的混乱布局。

### 4. 固定关系端口

为 sequence、spawn、task execution、result、retry/recovery 定义不同端口 side/order。incoming、
outgoing、result、recovery 不得全部落在节点左右中点。箭头必须停在目标卡片外边界，不能压住标题、
正文、状态或徽章。

### 5. 边捆绑与标签

- 同一父节点的多个结构分支允许共享短母线；
- 不同关系语义不得捆绑成无法区分的一条线；
- 激活边显示“分支”“执行”“结果”“恢复”“重试”短标签；
- hover/focus/选择时同时高亮 source、target、完整路径和标签；
- 其他边降低到约 10%-20% opacity，但端点保持可读；
- 键盘用户可以通过关系列表或标记选择边，不要求精确点击 SVG 细线。

### 6. 图层和障碍物

普通边必须位于 node/card/region header 下层。selected edge 可以增强，但仍不能覆盖卡片内容。

ELK/局部 router 的画布世界坐标障碍至少包含：

```text
semantic node
collapse group
region/lane header
```

status badge 和 expand button 位于 node 内，端口必须避开其内容安全区。toolbar、relation selector
和反馈浮层属于屏幕坐标覆盖层，不得错误地作为 ELK 世界坐标障碍；应通过 viewport padding/inset
保证首屏节点、箭头和标签不被覆盖。

不要使用动画流光、大面积 glow 或多色渐变。主骨架保持克制，结果、恢复、重试只在激活时使用语义
颜色。颜色不能成为唯一信号。

### 7. 视口

- 首次 fit 以 node/region 结构 bounds 为主；
- 默认隐藏的次要关系不进入初始 fit bounds；
- 超出阈值的 route bounds 不能继续缩小全图；
- 提供“适配执行结构”，必要时另提供“适配当前关系”；
- 普通选择、Inspector、Timeline、Payload 继续保持 viewport transform；
- 用户显式定位关系、main Run 或异常时允许移动视口。

## 六、量化测试要求

### 1. 路由指标

对每条当前可见的非 sequence 边计算：

```text
manhattan_distance = abs(source_port.x - target_port.x) + abs(source_port.y - target_port.y)
route_length = 所有 segment 长度之和
detour_ratio = route_length / max(manhattan_distance, 1)
```

最低要求：

- 普通结构边最多 3 个 bend，`detour_ratio <= 1.6`；
- 复杂 recovery/replacement 最多 5 个 bend，`detour_ratio <= 2.2`；
- 非端点画布 bounds 保持至少 12px 图坐标 clearance，并在实际 viewport transform 下保持至少 2px
  屏幕 clearance；
- 默认结构骨架 crossing count 为 0；
- 三子 Agent 默认图不存在触及整图极端边界的外绕线；
- 相同输入重复布局及输入数组乱序后路径拓扑稳定；
- 阈值如需调整，必须先提供真实统计和截图依据，不得只为通过测试放宽。
