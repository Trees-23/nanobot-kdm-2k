# 陈文驰周报工作提取（记忆层为主）

> 整理口径：基于 `_other/周报` 中署名“陈文驰”的工作进展，按计划日期合并同周重复记录；不把“本周计划”写为已完成事项。本文完整聚焦 Agent 记忆、知识库、记忆产品化及其工程支撑，文末简列其他署名工作。

## 工作主线概览

陈文驰的工作经历了两代记忆系统：先建设以 mem0 为底座的记忆中间层，完成身份、权限、审计、检索和工程化；再转向面向编程 Agent 的新版系统，以“原始证据 → 正式记忆 → 使用反馈 → 低频整理/Skill 蒸馏”为主线，补齐评测、治理、用户可见和生产可靠性。

## 时间线提取

### 2026 年 3—4 月：记忆中间层从设计到可运行

- 完成 Agent 记忆系统调研和整体设计文档，定位为统一的记忆接入、治理、审计和管理中间层。
- 启动实现：身份初始化、写入、召回、删除、管理查询、编辑和审计主流程；以租户、项目、角色三层范围隔离记忆；形成内核、治理层、管理能力的分层思路。
- 增加 LLM 决策层、非轮询 Outbox Dispatcher、身份标识与健康检查；将接口按 Agent / 租户管理员 / 平台管理员拆分，配套 Docker、日志和 Agent CLI Skill。
- 打通长上下文分块、提取、去重，补齐会话 ID 和短期记忆；重写 projection 以正确映射更新、删除；补齐审计身份、单测和集成测试。
- 清理 RQ Worker、内嵌 Dispatcher、遗留环境变量及无效代码，收敛后端与 CLI 接口；避免启动时误建 SQLite。

### 2026 年 4 月末：mem0 适配、离线化和插件化

- 升级 mem0 至 2.0.1，适配 Anthropic；增加 JSON 自动修复，增强弱模型输出的可用性。
- 修复强制英文存储、自动加载历史导致记忆串用、批次共享状态非线程安全和高并发可用性等问题；通过补丁解决中文分词和 spaCy 模型部署门槛。
- 移除 HuggingFace 实时下载 Tokenizer 的依赖，实现离线启动；完成 Docker/Compose、自动数据库迁移和全局配置精简。
- 增加模型上下文窗口数据和更新机制；分离 Admin Key 与 Agent 身份 Key 的写入权限；实现记忆演示页面。
- 将记忆导入改为故障不影响核心链路的插件机制，并实现从 AI 员工数据库导入会话数据。

### 2026 年 5 月：质量评测、并发治理与可运营后台

- 建设记忆评测体系：每个专题在独立空间执行“清空记忆 → 写入项目文档 → 问答 → 独立 LLM 裁判评分”。题集覆盖事实、多知识综合、流程和知识更新；评分同时检查答案与检索证据，防止模型靠外部常识得分。
- 支持最多三轮检索：首轮证据不足时基于已有证据生成新检索词；保存答案、命中证据、评分、扣分原因、红线问题和检索过程，定位“没搜到 / 搜到没用 / 使用旧事实 / 组织错误”。
- 比较不同推理强度、提示词和 Reranker 开关，以评测数据选择配置；Reranker 保持可配置而非默认启用。
- 为异步写入增加 lease heartbeat；审查并修复并发、锁、连接和资源生命周期问题；对写入、Worker、projection、召回建立性能 trace。
- 将候选合并从两两比较的 `O(n²)` 优化为先分桶后组内比较的近线性策略，并明确候选阶段只去重、事实冲突留给后续变更规划处理。
- 交付管理后台：概览、列表/详情/写入、导入导出、诊断、操作记录、审计日志；优化分页、PostgreSQL 查询、自动重试与失败收敛。召回侧增加近期召回加权、LLM 过滤和命中率统计。

### 2026 年 6 月：检索体系和新版记忆系统 MVP

- 从零交付知识库初版：文件管理、文档分块、导入导出、并发索引和失败清理；采用 **BM25 + 摘要向量 + 原文向量** 三路检索，并支持查看原文片段和召回测试页。
- 在召回结果中提供更新时间，让 Agent 判断事实时序；对空文档、JSON 输出和目录重建等边界情况做容错。
- 建立任务上下文感知召回：调用方说明“将做什么、需要什么、不需要什么”，据此过滤；采用“先摘要、给理由后按 ID 读详情”的两段式读取。
- 增加租户、项目、角色三级全局摘要；新会话时注入摘要；夜间对新增或变更记忆做增量摘要和超限压缩。
- 记录完整召回行为数据：任务动机、系统曝光摘要、详情读取及理由，与会话结果关联，作为后续归因和价值评估基础。
- 重新组织后台任务代码：Worker 管流程和用例，Pipeline 串业务步骤，Builder/Validator 处理细节。
- 完成新版记忆 MVP：会话先进入缓冲区保存为原始证据，再经提取 Agent 形成候选记忆和 Skill 线索，经巩固 Agent 新建/更新/合并/忽略为正式记忆；做梦 Agent 根据使用反馈清理、压缩、降权；蒸馏 Agent 将稳定重复流程发布为 Skill。
- 将个人/项目记忆组织为虚拟文件系统，向 Agent 提供 `ls/tree/rg/cat`，以“摘要 → 搜索 → 详情”的渐进披露方式使用。

### 2026 年 6 月末—7 月：产品化、反馈闭环与生产可靠性

- 建设个人记忆中心与管理控制面：个人概览、搜索、详情、来源、隐藏/恢复、删除请求、纠正提交、项目共享设置；管理端覆盖租户、命名空间、记忆、Skill、用户配置、Agent 运行、审计、诊断和性能分析。
- 把 Agent 运行沉淀为可查询、回放的记录，保存模型调用、工具调用、结果和最终输出；后台任务从独立 Worker 收敛到 API 单进程，模型不可用时延后 LLM 任务。
- 将后台界面从低密度卡片调整为高密度列表、分栏详情、紧凑筛选和固定操作区；完善用户对“系统记住了什么”的查看、编辑、隐藏和恢复体验。
- 将分散的正式记忆收敛为一套主数据模型；允许 Agent 通过 CLI 在权限范围内新建、更新、隐藏、删除，个人记忆和项目共享记忆采用不同权限边界。
- 参考 Claude Code：每轮先查看有限的最近记忆元数据并保守预取；提醒“记忆不是实时事实，代码/配置/状态须重新验证”；以关键词、触发条件、验证要求等元数据指导召回。
- 重构反馈：记录查询目的和任务后的有用/无用/缺失反馈，计算记忆价值，用于保留、合并、降权、补充或删除。
- 限制可写入记忆类型为用户偏好、用户反馈、项目外部事实、参考资料来源；合并数据库迁移和后端入口，更新 Memory Skill。
- 增加预取去重、摘要条数/字符预算和截断提示，按“最新 + 最近使用”排序；设计召回内容反馈环防护，避免已召回内容再次写入造成自我强化。
- 升级数据库框架和仓库层，统一数据编号、权限和后台任务状态；为 Agent 设置超时、工具错误、模型调用、重试、对话轮数等硬边界，并修复停止竞态、状态未取消、迁移和流式用量问题。
- 优化抽取与做梦：通过工具/提示词调整将周报记录的做梦模型调用从 19 次降至 12 次、抽取调用从 11 次降至 3 次；增加上下文规模感知、模型故障分类和恢复重试；修复格式错误死循环、状态倒退、Skill 导出回滚及共享记忆拦截问题。
- 增加在线实时日志诊断、端到端回归、生产包和部署配置；将写入缓冲上限提升到 100 万字符，并保持静默窗口策略。

## 记忆层设计结构（由周报归纳）

```text
会话/文档
  ↓ 原始证据缓冲区
提取 Agent ──→ 候选记忆 / Skill 线索
  ↓
巩固 Agent ──→ 正式记忆（个人 / 项目；带摘要、来源、时间、元数据）
  ↓                         ↘ 虚拟文件系统 + CLI 检索
使用行为（曝光、读取、引用、反馈）  → 价值信号
  ↓
做梦 Agent（清理、压缩、合并、降权） / 蒸馏 Agent（Skill）
```
