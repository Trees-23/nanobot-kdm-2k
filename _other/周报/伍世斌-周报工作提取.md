# 伍世斌周报工作提取

> 整理口径：基于 `_other/周报` 中署名“伍世斌”的工作进展，按计划日期合并 07 前/07 后/07 尾巴中的重复周次。本文记录已写入“本周工作进展/工作内容”的事项；“下周计划”单独标为后续方向，不作为已完成成果。

## 工作主线概览

伍世斌的工作主要围绕三条主线展开：

1. **Agent 能力进化**：UguardAgentRouter、UguardAgentSkill、SkillClaw、Evolver、OpenSpace，以及基于 GRPO 的训练、评估和策略选择闭环。
2. **业务智能体与 RAG**：面向销售、人事、咨询等部门建设业务 Agent，完成 RAG V1、知识库接入、敏感数据约束和部门隔离。
3. **数据与模型能力**：黑样本提示词/图片生成、垂直领域模型微调、数据生成 Agent、OCR 方案和多模态能力调研。

## 时间线提取

### 2026 年 4 月：自进化框架场景验证与选型

- 在漫画 Agent 上完成 OpenSpace + Evolver 集成测试，发现创意类、离散任务的反馈回路太短，策略演化增量不明显，因此停止该路径以降低成本。
- 将核心验证场景切换为长路径小说 Agent，利用长文本的逻辑连贯性和设定一致性检验进化上限。
- 初步跑通 Evolver 驱动小说 Agent 根据章节反馈自动迭代 Prompt 策略；推进 OpenSpace 的底层协议对接和技能原子化拆解。
- 识别出长期记忆缺失、技能调用冲突、复杂技能库目录构建效果不佳等集成瓶颈，并讨论 BGE/Qwen Embedding、Evolver 与 OpenSpace 中层通信等方向。
- 在小说创作场景对比 SkillClaw 与 OpenSpace：SkillClaw 的“打回—重修—精馏”提高输出语义纯度，OpenSpace 更适合多路并发稳定执行。
- 跑通“Evaluator（Gemini 裁判）→ Actor（Agent 执行）”自动反馈链路，验证系统可以自动发现错误并驱动 Skill Bank 演化。
- 复盘发现：递归修正会导致上下文迅速膨胀并触发 502；技能库增长后单纯 Prompt 注入不足；融合后的 Agent 状态机在多任务并发时可能进入混乱状态。

### 2026 年 5 月 6—9 日：RL 训练与评估闭环原型

- 完成 Tinker-Atropos 到 SkillClaw 的适配，跑通 **GRPO + LoRA**；打通 SQLite 会话、轨迹、奖励和训练的数据流，并修复 SQLite 异步化与并行处理问题。
- 建立自动轨迹采集、checkpoint 管理、本地训练、固定评估任务集和训练前后对比报告，形成“训练 → 评估 → 对比”的初步闭环。
- 使用 Streamlit WebUI 管理 RL 配置、训练数据、checkpoint 和轨迹，支持自动采集和一键训练。
- 调研 Hermes、OpenSpace、SkillClaw 的模块边界，发现 SkillClaw 直接接入天磊虾存在稳定性和安全风险。
- 明确局限：尚未接入 GPU 和真实模型，缺少大规模数据及性能基准；reward 和 success 判断较基础，尚未引入 LLM Judge 或用户反馈；复杂对话的 state/action/reward 仍难抽象。

### 2026 年 5 月 11—29 日：UguardAgent 融合、训练模块与数据清洗

- 完成 UguardAgent 融合工作：清理冗余代码和功能、修复遗留 Bug、增加进化前后 diff 对比，并将默认 PPO 改为 GRPO。
- 优化旁路接入的 session 处理，为每个 session 内容增加 ID，避免多用户并发时冲突；依据插件模板开发 UguardAgent 接入插件并接入天磊虾测试，但早期存在收不到消息的问题。
- 为进化模块加入外部大模型评估能力：针对事件中调用到的 Skill Prompt 给出评估和修改意见；扩展 WebUI，展示 Skill 编号及实际使用的 Prompt 句子，同时复盘 KPI、Case 分组和强化学习页面的信息冗余。
- 完成强化学习模块的第一轮设计：选择 GRPO；每 5 次事件记录一次 RL 数据；将完整任务或 Agent 挂起超过 30 分钟定义为事件；用 `sessionID` 去重；由 WebUI 记录数据并发送到 GPU 服务器训练，训练结束后回传结果，操作人员基于 reward 等指标选择是否接收新策略。
- 完成 UguardAgentRouter 初步接入：筛选训练数据和权重、优化 WebUI、接入 Agent Console 后端并部署。
- 完成 UguardAgentSkill 训练模块：理解并重构微软 SkillOpt，填写训练参数，开发和重构 WebUI，加入训练数据可视化。
- 完成 Skill 数据清洗模块：处理日志和用户对话，支持按 `agentID` 全量或定向筛选，产出训练模块需要的文本；将清洗模块与训练模块合并并接入 Console，部署状态仍需继续确认。
- 明确 Router 与 Skill 的关系：Router 负责选择更合适的 Skill，Skill 负责持续演化，两者功能互补但 Router 需要 GPU 资源，是否合并部署需要权衡。

### 2026 年 6 月 1—18 日：训练参数与业务智能体方案收敛

- 完善 UguardAgentSkill：增加显式 `step` 等训练参数；优化页面并对齐 Agent Console；测试发现训练页面慢更新、智能门控等参数开启后训练分数自述提升约 6%，代价是训练速度和 Token 消耗上升。

## 设计与工程要点

| 方向 | 已提取做法 |
| --- | --- |
| 进化闭环 | 轨迹采集 → reward/评估 → 策略或 Skill 修改 → 前后对比 → 人工选择是否接收 |
| 评估机制 | Evaluator-Actor、固定任务集、训练前后对比、diff、reward 指标 |
| 事件建模 | 完成任务或长时间挂起作为事件；按 session ID 去重；每 5 次事件记录 RL 数据 |
| Skill 体系 | Router 负责选择，Skill 负责演化；SkillClaw 侧重质量控制，OpenSpace 侧重并发执行 |
| 运行约束 | 关注 Token、递归修正、GPU 成本、MOE 不确定性、状态机并发混乱和技能检索精度 |
| RAG | chunk 与检索策略、敏感数据专人入口、重复数据替换、部门隔离、插件接入、稳定性优化 |
| 数据与模型 | 黑样本提示词/图片、OCR、Qwen 27B 微调、数据生成 Agent、外部视觉审核模型 |

## 周报中暴露的主要问题

- 进化框架直接接入 Agent 时存在稳定性和安全风险，状态机在多任务场景可能混乱。
- 递归修正容易造成上下文膨胀、502 和高 Token 成本；技能数量增加后，单靠 Prompt 注入不够。
- RL 原型缺少 GPU、真实模型、大规模数据和成熟 reward；训练指标与业务价值之间还需要更多验证。
- 训练数据质量直接影响 loss、生成速度和模型效果；RAG 早期受样本量、召回速度和敏感数据边界影响。
- 复杂场景需要清晰的中层协调协议，否则 Evolver 的策略抽象和 OpenSpace 的工具/技能执行可能出现“1+1<2”。
