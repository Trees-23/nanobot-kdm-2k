# 王延周周报工作提取（Runtime / AI 员工为主）

> 整理口径：基于 `_other/周报` 中署名“王延周”的工作进展，按计划日期合并同周重复记录；“本周计划”不作为已完成事项。本文优先完整保留 AI 员工、运行时、智能体平台及其直接支撑工作，并在文末列出其他相关产出。

## 工作主线概览

王延周的工作从早期的智能体平台调研，逐步发展为一套面向长期任务的 AI 员工运行平台：沙箱与工作区承载执行，实例与任务承载状态，事件与控制台承载观测和干预，插件/Skill/工具承载扩展，心跳和恢复机制承载长任务可靠性。

## 时间线提取

### 2026 年 1—2 月：可观测、并发与平台方向验证

- 为大模型报告 Agent 建设基于 `trace_id` 的全链路日志、管理员及日志表、错误堆栈与参数透传；完成任务队列监控、任务级联取消和实时状态追踪。
- 将并发控制从“大任务级”调整为“子任务级公平调度”，降低任务互相阻塞和系统负载。
- 调研 OpenClaw、OpenCode、Evolver：关注上下文压缩、FTS/混合检索、心跳保活、记忆污染、多智能体交互、能力自进化等问题；结论是通用运维型 Agent 不足以直接承担精细开发，需要独立的开发运行平台。
- 产出 AI 员工云平台初步架构：员工本体、会话与沙箱、多智能体交互、云 Skill 管理、C/S 产品形态，以及配套架构图和流程图。

### 2026 年 3 月：从单 Agent 到沙箱化多 Agent 平台

- 参考 nanoclaw 实现单智能体核心框架，接入 Telegram，加入状态机、调试状态展示、使用文档和测试框架。
- 构建 AI 员工基础 Docker 镜像，预装 `git`、Python 等常用工具；开发 Python 沙箱集群管理服务，用 HTTP 接口管理容器生命周期，并提供快捷控制脚本。
- 实现多智能体团队协作工具：Agent 列表、`@` 消息、消息历史、忙闲状态管理；在 MCP 与“Skill + CLI”之间选择后者，理由是更灵活、可维护。
- 设计协调者（Orchestrator）及团队开发 Skill：协调者仅负责规划和协调，通过团队工具驱动其他 Agent 执行。
- 引入消息队列解除忙状态消息阻塞，通过 `AGENT_ID` 隐式注入区分 CLI 调用身份。
- 将核心代理从 TypeScript 重写为 Python，补全类型、事件和路由模块，并以 Docker 实机验证；工作流收敛为 `planner / implementer` 双角色。
- 建设 API Channel 与 CLI 客户端用于闭环自测；完善日志链路及管理节点、工作区的小型控制台。
- 完成平台 MVP：按开发、科研等场景隔离多工作流；建立最小工作流及长工作流验证；增加任务暂停、重启、中止、跳过，队列驱动、实例自动回收、主实例切换与前端心跳事件。
- 为控制台设计 WebSocket 连接池：后端与智能体空间保持连接并持久化，向用户前端会话广播，兼顾消息可靠保存和实时呈现。补充工作区准备/收尾 Agent，规范 Git 分支、提交、PR 与 `ACTION.md` 决策记录。

### 2026 年 4—5 月：Go Runtime 的领域分层与可恢复执行

- 启动并推进 Go 版 AI 员工 Runtime 重构，建立：
  - **配置中心**：统一运行配置；
  - **实例管理层**：实例创建、启动、持久化、恢复，支持运行时切换不同模型供应商 SDK；
  - **任务系统**：任务绑定单一实例，任务状态和日志按任务隔离；
  - **事件总线**：打通主编排链路；
  - **SDK 服务**：归一化 Codex 与 Claude 工具事件。
- 统一控制台与后端通信协议，使事件携带完整追踪链路；联调“工具请求 → 审批 → 执行 → 结果返回 → 消息渲染”，修复结果关联、审批状态与渲染不一致问题。
- 将主编排器提升到全局 `system` 目录统一维护提示词；区分交互式任务和自动任务，由主编排器创建、启动、删除；工作流结构化数据实时渲染为流程图。
- 建设会话管理，支持按用户、容器、状态、工作流、关键词查询；完善 WebSocket 重连和 Codex 会话过期的多层降级思路。
- 建立双层管理 API：结构化 API 面向前端，文件系统 API 面向 Agent；运行时 Skill 可对 Skill/工作流配置仓执行 `ls/read/write/find/grep` 等操作。
- 实现 Hook 模块（持久化模型、订阅/通知、任务状态变更回调）、插件运行器、环境变量注入、渲染输出和插件目录快照挂载，支持工作区级插件隔离；接入 Memory 插件。
- 建立 CCH Bridge，处理控制台—运行时临时密钥、工作区生命周期及安全修复，打通可信通信链路；优化任务历史摘要查询和 CLI 历史加载性能。
- 增加控制台/运行时插件生命周期（工作区创建和销毁、任务会话 Hook、提示词注入）、快速/编排双模式、运行时轮次事件和 CLI 优化。

### 2026 年 6—7 月：可靠性、工具体系与外部接入

- 修复工作区回收事故：将物理删除记录改为非破坏性停容器保记录；处理孤儿容器；重启遇到 404 时兜底重建并恢复数据库数据。
- 支撑复杂业务智能体：构建保活 Skill、交互确认门、组件手册 Skill；在反例中复盘“业务仓全链路未测通”，沉淀研发纪律。
- 完成工具管理服务：标准工具协议 + `tool-cli`，管理员配置公共工具、用户单独填写 API 密钥；通过 `available_tool_groups` 和 `tool-cli describe` 渐进加载工具；支持 MCP 配置的确定性解析与 AI 补全说明。
- 设计外部系统接入框架：账号开通开发者、应用绑定项目并隔离记忆、由 API 调度 Agent；区分交互式会话与非交互式任务，后者包含自动执行、静止检测、交付物验收补交、重试次数配置和失败标记。
- 规划工作区回收与交付物临时保留（30 天可下载），并持续改进创建工作区与工具选择的控制台交互。

## 与运行时直接相关的设计要点

| 设计面 | 周报中的具体做法 |
| --- | --- |
| 执行隔离 | Docker 沙箱、工作区级插件隔离、任务绑定单一实例、多工作流职能隔离 |
| 生命周期 | 实例创建/持久化/恢复/启动；任务暂停、重启、中止、跳过；非破坏性回收与 404 重建 |
